# 점프부기 Web 0.1

기존 Pygame 게임을 브라우저로 옮긴 독립 프로토타입입니다. 실행에 필요한 이미지와 충돌 마스크를 이 폴더에 복사했으므로 `web/`만 따로 옮겨도 실행됩니다. 웹 실행은 Python 게임이나 `txt/high_score.txt`를 읽거나 쓰지 않으며, Pygame의 논리 화면은 480×360으로 유지합니다. 현재 두 버전의 낮·밤 슬롯 길이는 25초입니다.

처음 공부한다면 [코드부터 읽는 web-srudy](../docs/web-srudy.md)를 먼저 읽으세요. 전체 구조는 [ARCHITECTURE](../docs/ARCHITECTURE.md#웹-이식본-구조), 최신 점검 결과와 한계는 [WEB_REVIEW](../docs/WEB_REVIEW.md), 미완료 작업은 [TODO](../docs/TODO.md)에 있습니다. 사용자용 학습 사본은 상위 `pygame/web-srudy.md`입니다.

## PC에서 실행

Windows에서는 `start_web.bat`을 더블클릭하고 표시된 주소 **http://127.0.0.1:8000/** 를 브라우저에서 여세요. Python 3.10 이상이면 되고 Pygame이나 npm 패키지 설치는 필요 없습니다.

터미널에서는 다음과 같이 실행합니다.

```powershell
cd web
python -B serve.py
```

다른 위치에서도 `python -B "웹폴더의 전체경로\serve.py"`로 실행할 수 있습니다. 서버는 항상 이 웹 폴더를 제공합니다. 종료는 서버 창에서 `Ctrl+C`입니다. 포트가 이미 사용 중이면 `python -B serve.py --port 8001`로 실행하세요.

`index.html`을 파일로 직접 열면 브라우저의 모듈·자산 보안 제한 때문에 실행되지 않습니다. 반드시 위의 HTTP 주소로 접속하세요.

## 휴대폰에서 실행

PC와 휴대폰을 같은 Wi-Fi에 연결하고 PC에서 실행합니다.

```powershell
python -B serve.py --host 0.0.0.0
```

PC에서 `ipconfig`로 Wi-Fi IPv4 주소를 확인한 뒤, 휴대폰에서 `http://PC의IPv4주소:8000/`에 접속합니다. 예를 들어 PC 주소가 `192.168.0.10`이면 `http://192.168.0.10:8000/`입니다. Windows 방화벽 안내가 나오면 사용하는 개인 네트워크의 Python 연결을 허용해야 합니다. `127.0.0.1`은 휴대폰에서 PC에 접속하는 주소가 아닙니다.

이 버전은 로컬 결과물이며 인터넷에 배포하지 않았습니다. 정적 호스팅에 올릴 때는 `index.html`, `style.css`, `favicon.svg`, `src/`, `assets/`를 동일한 디렉터리 구조로 업로드하면 됩니다.

## 조작과 화면

| 상황 | PC | 모바일 |
| --- | --- | --- |
| 시작 | 인트로에서 아무 키 또는 재생 아이콘 | 화면 터치 또는 재생 아이콘 |
| 점프 | Space | 게임 화면 터치 |
| 정지·재개 | Esc 또는 중단 화면의 재생 아이콘 | 화면 이탈 시 자동 정지, 재생 아이콘으로 재개 |
| 다시 시작 | 게임오버 후 Enter 또는 다시 시작 아이콘 | 다시 시작 아이콘 |

처음에는 원본 인트로 그림 전체를 비율 유지해 표시합니다. 테두리처럼 보이던 외곽의 옅은 배경은 표시용 캔버스에서만 흰색으로 정리하며, 원본 PNG는 보존합니다. 2초 뒤 시작 입력을 받으며, 입력 전까지 인트로가 그대로 남습니다. 시작하면 흰 배경의 부기 뒤로 배경이 1.25초 동안 나타납니다. 시작 입력은 점프에 중복 사용하지 않습니다. 충돌하면 빨간 GAME OVER 메시지와 Enter 재시작 안내를 표시하고 점수·시간·이동·애니메이션이 멈춥니다. Enter 또는 다시 시작 아이콘으로 재시작하며, 게임오버에서는 Esc나 Space로 재개되지 않습니다. 플레이 중 Esc의 일시정지·재개 동작은 유지합니다. 다시 달리기는 첫 연출을 생략합니다. 다른 탭·창으로 이동하면 자동으로 정지하며, 돌아온 뒤 직접 재개합니다.

논리 게임 영역은 **640×360**, 부기의 x 위치는 `src/engine.js`의 `RULES.playerX`에서 설정합니다. 세로 위치·크기·중력·점프 속도는 현재 Pygame 기준을 유지합니다. CSS 확대와 별개로 가로 플레이 영역 자체를 늘렸습니다. 게임 아래의 고정 정보 줄에 `SCORE`와 `TIME`을 표시합니다. 점수 줄은 시작 대기부터 게임오버까지 같은 높이를 유지하며, 종료 시 최종 점수와 시간이 그대로 남습니다. 시작·재개·재시작은 글자 없는 아이콘이며 접근성 이름은 유지합니다. 상단 일시정지 버튼은 표시하지 않습니다. PC에서는 게임과 기록을 약 75:25로 배치하고 두 카드의 위아래 높이를 맞춥니다. 랭킹은 여백과 내 기록 영역을 간결하게 정리하고, 목록이 길면 보드 안에서 스크롤합니다. 너비 1000px 이하에서는 게임 화면이 작아지지 않도록 세로로 배치합니다. 랭킹보드는 시작 대기·플레이·일시정지·게임오버·재시작에서 같은 UI 영역에 항상 표시합니다. 모바일은 게임 화면 → 점수/결과 줄 → 랭킹보드 순서를 유지합니다. 게임오버에서 카드나 목록 컨테이너를 다시 만들거나 옮기지 않고, 기존 방식으로 기록 내용만 갱신합니다. 가로 화면을 권장하지만 세로 화면도 플레이할 수 있습니다.

## 유지한 규칙

- 1단 점프, 화면에 보이는 프레임의 알파 마스크에 따른 충돌
- 생존 1초당 1점, 장애물 통과당 10점, 상찌 무리는 마리당 10점
- 25초마다 낮·밤 전환, 봄→여름→가을→겨울의 8슬롯 순환과 4초 배경 혼합
- 현재 속도 곡선과 패턴 선택·회복 간격, 여름 날갯짓·비행, 가을 한성캣, 겨울 상찌의 순차 해금
- 둘째 봄부터 인사 캐릭터 점프, 상찌 무리·개별 점프·구덩이 탈출
- 달리기·넘어지기·하품·책 떨어뜨리기, 비행 상·중·하, 구덩이 빠름·느림
- 높은 친구는 아래로, 지상·낮은 친구는 점프로 통과

장애물 동작의 기준 x좌표는 `RULES.playerX`에 맞춰 기존 회피 여유를 유지합니다. 화면 폭에 비례해 장애물 간격을 늘리지 않습니다. 충돌 검사는 빠른 이동에서도 몸체를 건너뛰지 않도록 작은 단계로 나눕니다. 모바일과 PC가 같은 엔진을 사용합니다.

## 기록의 범위

첫 접속에 독립 `player_id`와 임시 `nickname`을 만들고 브라우저 `localStorage`에 저장합니다. 닉네임은 식별 키로 사용하지 않습니다. 게임오버 때만 결과를 저장하며, 최근 기록과 최고 기록을 포함해 최대 50개를 보관합니다.

첫 플레이 전 기록판은 **예시**로 명확히 표시됩니다. 플레이 후에는 해당 브라우저의 실제 플레이 결과 상위 5개를 점수순으로 보여줍니다. 여러 사용자의 온라인 랭킹이 아닙니다. Pygame의 `txt/high_score.txt`와도 별개입니다. 저장소가 차단되면 오류 대신 이번 접속의 메모리에 기록하며 안내를 표시합니다.

결과 필드는 `player_id`, `nickname`, `run_id`, `score`, `survival_time`(초), `game_version`, `played_at`(ISO 시간), `death_obstacle`, `max_speed`(배율), `device_type`입니다. 서버·DB·외부 전송은 없습니다. 서버 랭킹과 실제 기기별 밸런스 조정은 후속 사용자 테스트 범위입니다.

## 폴더와 검사

```text
web/
├─ index.html / style.css / favicon.svg
├─ src/
│  ├─ app.js                 화면·입력·첫 실행·게임오버 연결
│  ├─ engine.js              공통 물리·장애물·충돌·득점·계절
│  └─ storage.js             브라우저 ID·기록 저장
├─ assets/                  별도로 복사한 PNG와 manifest.json 충돌 마스크
├─ serve.py / start_web.bat  Python 표준 라이브러리 로컬 서버
├─ tests/                   Node 내장 테스트
└─ tools/
   ├─ export_assets.py      기존 자산을 읽어서 web/assets에만 내보내기
   └─ browser-smoke.mjs     설치된 Chrome/Edge의 PC·모바일 브라우저 검사
```

개발 검사에는 Node 22 이상을 권장합니다. npm 설치 없이 실행할 수 있습니다.

```powershell
cd web
node --test tests/*.test.js
```

로컬 서버가 실행 중이면 브라우저 검사도 가능합니다. 브라우저 검사 도구는 Node 22 이상과 설치된 Chrome 또는 Edge가 필요하며, `.qa/`에 화면과 보고서를 저장합니다. 모바일은 브라우저의 기기 모사 검사입니다. 실제 휴대폰에서의 터치감·성능·난이도는 별도 확인해야 합니다.

```powershell
node tools/browser-smoke.mjs http://127.0.0.1:8000/
```

2026-11-22 검증: Node 자동 테스트 21개와 Chrome의 PC·모바일 세로·가로 흐름 검사를 통과했습니다. 원본 인트로 전체 표시·입력 전 유지, 설정된 부기 위치와 고정 SCORE·TIME 정보 줄, 키보드·터치 입력, 일시정지, 게임오버 시 1회 기록 저장, 새로고침 후 식별자·기록 유지, 재시작, 랭킹 상시 표시·동일 DOM·위치 유지, 상단 일시정지 버튼 숨김을 확인했습니다. 브라우저 콘솔 오류는 0개였습니다. PNG 83개·충돌 마스크 74개도 현재 Pygame 자원과 일치했습니다. 상세 범위와 실행 환경은 [WEB_REVIEW](../docs/WEB_REVIEW.md), 로컬 화면·JSON은 `.qa/`에 있습니다.

자산 재생산만 부모 Pygame 소스와 Pygame 설치가 필요합니다. 웹을 실행할 때는 필요 없습니다. 기존 자산을 가공해 별도로 저장하며 원본을 덮어쓰지 않습니다.

```powershell
python -B tools/export_assets.py
```
