# 점프부기

점프부기는 장애물에 따라 뛰어넘거나 아래로 달려 통과하는 Pygame 러너입니다. 기준 폴더는 `jumpbugi/`입니다.

이 버전은 **HansungRun Pygame Prototype 1.0**의 기준본입니다. Pygame의 논리 화면은 480×360으로 유지하며, 이후 라즈베리파이 이식과 게임 규칙 참고용 원본으로 사용합니다. 웹 버전은 별도 프로젝트에서 설계합니다.

GitHub 저장소는 [개인 jumpbugi](https://github.com/gusdnrdl11/jumpbugi)와 [튜터링 jumpbugi](https://github.com/hansung-tutoring/jumpbugi)이며, 두 저장소의 기본 브랜치는 `main`입니다.

## 실행과 검사

확인 환경은 Python 3.13.15, pygame 2.6.1입니다. jumpbugi 폴더에서 실행합니다.

```powershell
python main.py
python -B -m unittest discover -s tests -v
```

상위 폴더에서는 `python -m jumpbugi.main`으로 실행할 수도 있습니다.

Space: 점프 / Esc: 정지·재개 / 게임오버 후 Enter: 재시작 / Ctrl+F4 또는 창 닫기: 종료

## 첫 실행과 재시작

처음 실행하면 사용자가 제공한 `image/intro.png`를 2초 동안 보여 줍니다. 그림에 ‘점프부기’ 제목이 포함돼 있어 별도 제목이나 말풍선을 겹쳐 그리지 않습니다. 이전 `image/start.png`·`image/start.jpg`는 보존합니다. 이후 흰 배경에서 상상부기가 달리며 ‘아무 키나 누르면 시작’과 조작 안내만 표시합니다. 입력 대기 화면에 게임 제목은 다시 표시하지 않습니다. 키를 누르면 부기의 위치와 달리기 동작을 그대로 이어 가면서 한성대 봄 낮 배경도 정상 게임의 시작 속도인 `BACKGROUND_SPEED × PHYSICS_HZ` 픽셀/초로 가로 스크롤을 시작합니다. 배경 알파만 1.25초 동안 0에서 255로 높여 흰 배경 위로 움직이는 풍경이 천천히 나타납니다. 부기는 페이드 없이 계속 달리고 시작·조작 안내는 함께 사라집니다. 시작에 사용한 Space는 점프 입력으로 중복 처리하지 않습니다.

시작 이미지는 실제 제목·캐릭터·소품이 있는 콘텐츠 영역을 기준으로 희미한 외곽 여백을 제외합니다. 캐릭터가 과하게 잘리지 않도록 작은 안전 여백을 둔 뒤, `object-fit: cover`처럼 비율을 유지해 480×360 화면 전체를 덮고 넘치는 부분만 중앙 기준으로 잘라냅니다. 제목은 이미지에 포함된 것만 표시하며 이미지 외곽에 반투명 테두리를 두지 않습니다. 원본 PNG는 수정하지 않습니다.

시작 이미지·입력 대기·배경 전환 중에는 점수·계절·장애물이 진행되지 않습니다. 배경 전환 중에는 추가 키 입력을 무시하며, 부기의 달리기와 배경 스크롤은 계속됩니다. 전환이 끝나면 배경 위치를 그대로 이어서 플레이를 시작하고 다음 갱신부터 장애물이 화면으로 들어옵니다. 게임오버 후 Enter를 누르면 첫 연출을 생략하고 한성대 봄 낮 배경에서 바로 재시작합니다. 시작 이미지 표시 시간은 `config.SPLASH_SECONDS`, 시작 배경 전환 시간은 `config.START_FADE_SECONDS`에서 조절합니다.

| 단계 | 화면과 진행 |
| --- | --- |
| 첫 이미지 2초 | ‘점프부기’ 제목이 포함된 `intro.png`를 전체 화면에 표시 |
| 키 입력 대기 | 흰 배경에서 상상부기 달리기, 시작·조작 안내만 표시 |
| 시작 전환 1.25초 | 달리는 부기 뒤로 스크롤 중인 배경만 나타나고 시작·조작 안내는 사라짐 |
| 플레이 | 배경 위치와 달리기 자세를 이어받고 장애물·점수·계절 진행 시작 |

캐릭터 파일은 상상부기 `bugi.png`·`bugi_run.png`, 한성캣 `hsucat*.png`, 상찌 `sj*.png`, 치킨 `chicken*.png`로 정리했습니다. 달리기·굴 파기·인사처럼 각 이미지의 동작을 파일명에 표시합니다.

## 계절 배경 순환

배경은 `봄 낮 → 봄 밤 → 여름 낮 → 여름 밤 → 가을 낮 → 가을 밤 → 겨울 낮 → 겨울 밤 → 봄 낮` 순서로 무한 반복합니다.

낮 또는 밤 하나가 한 슬롯이며 기본 길이는 `DAY_NIGHT_INTERVAL=25`초입니다. 봄 낮 0슬롯, 봄 밤 1슬롯, 여름 낮·밤 2·3슬롯, 가을 낮·밤 4·5슬롯, 겨울 낮·밤 6·7슬롯 순서입니다. 8슬롯인 200초가 지나면 두 번째 봄 낮으로 이어집니다. 배경은 슬롯 경계에서 4초 동안 부드럽게 섞습니다. 일시정지·게임오버에서는 전환이 멈추고 재시작하면 봄 낮으로 돌아갑니다.

`total_slots_passed`는 누적 슬롯 번호, `current_slot`은 0~7의 화면 순서, `season_cycle_count`는 완료한 사계절 수입니다. 장애물 해금과 난이도는 이 진행 단계를 사용합니다. 슬롯의 실제 길이를 20초나 30초로 바꾸어도 해금 슬롯은 그대로 유지됩니다.

계절별 낮·밤 PNG 8장은 시작 시 한 번 불러옵니다. 순서는 `config.py`의 `BACKGROUND_FILES`에 있으며 계절이 봄으로 돌아와도 누적 속도와 점수는 유지됩니다.

## 장애물 패턴

기본 꾸꾸·꼬꼬는 `chicken_wave.png`, 기본 한성냥이(한성캣)는 `hsucat_wave.png`의 인사 4프레임을 사용합니다. 꾸꾸·꼬꼬는 흰색·갈색 두 캐릭터를 한 장애물로 유지한 146×120 크기이며, 한성냥이는 85×120입니다. 양발 중심과 발바닥 높이를 맞춰 인사 중 몸통이 흔들리지 않게 하고 지상 발끝은 y=358에 맞춥니다. 이전 `chicken.png`·`hsucat.png`를 포함한 원본 PNG는 보존합니다.

게임의 첫 1년은 사계절 낮·밤 8개 배경이 한 바퀴 도는 8단계입니다. 기본 두 종류는 첫 8단계 동안 지상에서 손만 흔들며, 플레이어가 점프로 넘어갑니다. 8단계 이후 새로 생성될 때에는 65% 확률로 점프를 선택하고 아래 세 패턴 중 하나로 움직입니다. 점프하지 않는 경우에는 계속 지상에서 인사합니다. 8단계 전에 생성된 장애물은 접근 도중 갑자기 점프하지 않으며, 재시작하면 첫 1년 조건으로 돌아갑니다.

| 점프 패턴 | 최고 상승량 | 플레이어의 회피 |
| --- | --- | --- |
| 높은 점프 | 192픽셀 | 아주 높이 떠오르므로 점프하지 않고 아래로 달려 통과 |
| 머리 위 점프 | 128픽셀 | 머리 바로 위의 좁은 틈으로 통과하므로 지상 유지 |
| 낮은 점프 | 12픽셀 | 낮게 뛰는 장애물을 플레이어의 점프로 넘어감 |

세 패턴 모두 공중에서는 인사 첫 포즈를 고정하고 착지 후 손 흔들기를 재개합니다. 높은 점프와 머리 위 점프는 플레이어와 수평으로 겹치는 구간에 머리 여유가 남도록 궤적을 계산합니다. 화면 표시와 충돌 판정은 같은 위치와 포즈를 사용합니다.

등장 조건·확률·높이는 `config.py`의 `WAVE_JUMP_UNLOCK_SLOT`, `WAVE_JUMP_PROBABILITY`, `WAVE_JUMP_HEIGHTS`에서 조절합니다.

추가 날갯짓 캐릭터는 `chicken_flap.png`의 흰색·갈색 지상형(높이 96픽셀)과 비행형(높이 80픽셀)입니다. 날갯짓 4프레임과 프레임별 충돌 마스크를 사용하며 기존 2단계 해금을 유지합니다. 비행형은 등장할 때 상·중·하 높이를 같은 확률로 선택하고 지나가는 동안 해당 높이를 유지합니다.

| 비행 높이 | 발끝 위치 | 회피 방식 |
| --- | --- | --- |
| 상 | y=170, 상상부기 머리보다 72픽셀 위 | 점프하지 않고 아래로 통과 |
| 중 | y=240, 상상부기 머리 바로 위 2픽셀 간격 | 가까워 보여도 지상 유지, 성급한 점프는 충돌 가능 |
| 하 | y=334, 지상 플레이어의 몸과 겹침 | 점프로 넘어가기 |

중간 높이는 모든 지상 달리기·날갯짓 포즈에서 아래 통과가 안전하도록 배치합니다. 세 높이 모두 통과하면 10점을 한 번 받습니다. 높이는 `config.py`의 `FLYING_LEVELS`·`FLYING_HEAD_GAPS`에서 조절합니다.

추가 한성캣은 달리기·거대 웅크리기·책 떨어뜨리기입니다. 달리기는 `hsucat_run.png`의 4프레임을 사용합니다. 책 한성캣은 기존 이름 `hsucat_book.png`를 유지하면서 실제 표시를 `hsucat_drop_book.png`의 4프레임으로 교체했습니다. 화면에 접근하면서 책 들기 → 놓치기 → 떨어뜨리기 → 바닥에 놓인 책 순서로 한 번 진행하고 마지막 자세를 유지합니다. 180×120 크기 안에서 공통 배율과 좌표를 사용하므로 책이 오른쪽으로 움직여도 캐릭터의 위치와 발 높이가 흔들리지 않습니다.

달리는 한성캣은 첫 가을인 4슬롯부터 일반 달리기·넘어지기 중 하나를 선택하고, 두 번째 봄인 8슬롯부터 높은 점프·낮은 점프를 더한 네 동작을 같은 확률로 선택합니다. 일반 달리기는 기존 네 포즈를 반복합니다. 넘어지기는 달리다가 `hsucat_fall.png`의 네 포즈로 이어지고 마지막 엎드린 자세를 유지합니다. 높은 점프는 최고 384픽셀 떠올라 정점에서 몸 전체가 화면 위로 사라지며, 상상부기는 점프하지 않고 아래로 통과합니다. 낮은 점프는 최고 24픽셀 떠오르며, 일반 달리기·넘어지기와 함께 플레이어가 뛰어넘습니다. 점프 중에는 첫 포즈를 고정하고 착지하면 달리기를 재개합니다. 네 동작 모두 통과하면 10점을 한 번 받으며 높은 점프 아래 통과도 같은 보너스를 받습니다. 선택한 동작은 등장 중에 바뀌지 않습니다. 첫 8슬롯 동안에는 두 점프를 선택하지 않습니다.

거대 한성캣의 기존 이름 `hsucat_crouch.png`는 등장 패턴의 구분으로 유지하고, 실제 화면에는 새 `hsucat_yawn.png` 한 장의 네 포즈만 사용합니다. 화면에 들어오며 입을 조금씩 벌려 하품하고, 입을 크게 벌린 마지막 자세를 화면 밖으로 나갈 때까지 유지합니다. 첫 자세로 반복하거나 다른 이미지로 바뀌지 않습니다. 입을 벌리는 진행 구간을 이전보다 약 31% 늘려 같은 속도에서 조금 더 천천히 하품합니다. 구간은 `HSUCAT_GIANT_YAWN_START_X`·`HSUCAT_GIANT_YAWN_END_X`로 조절합니다.

거대 한성캣의 네 포즈는 투명 여백을 제외하고 공통 배율로 비율을 유지합니다. 기존 202×120 크기의 표시 영역 안에서 이전 캐릭터가 차지하던 콘텐츠 크기·가로 중심·발바닥 위치에 맞춰 몸통이 갑자기 커지거나 위아래로 흔들리지 않도록 합니다. 기본 인사 한성냥이의 85×120보다 넓은 장애물이며, 원본 PNG는 수정하지 않습니다. 첫 가을인 4단계 해금·지상 위치·점프로 넘는 방식과 통과 보너스 10점은 유지합니다. 일시정지·게임오버에서는 선택한 동작과 포즈가 멈춥니다.

기본 상찌는 `sj_wave.png`의 2×2 시트를 나눈 손 흔들기 4프레임을 사용합니다. 각 프레임은 몸통과 발 위치를 맞춘 42×40 크기이며, 이전 `sj.png` 원본은 보존합니다. 첫 사계절이 끝나는 8단계부터 기본 상찌가 선택되면 두 마리 또는 세 마리가 무작위로 붙어 등장합니다. 마리 사이 간격은 3픽셀이고 전체 너비는 각각 87·132픽셀입니다.

상찌 무리는 각 마리가 독립적으로 지상 유지·낮은 점프·높은 점프를 선택합니다. 65% 확률로 점프를 선택하며 점프할 때는 두 높이를 무작위로 고릅니다. 낮은 점프는 최고 18픽셀로 플레이어가 뛰어넘고, 높은 점프는 최고 306픽셀로 상상부기가 점프한 상태에서도 그 아래를 통과할 수 있습니다. 따라서 같은 무리에서 높은 상찌 아래를 지나면서 낮은 상찌를 넘을 수 있습니다. 출발 위치는 마리마다 다르게 정하고, 공중에서는 첫 포즈를 고정하며 착지 후 손 흔들기를 재개합니다.

기본 한 마리 상찌와 달리기 상찌도 8단계 이후 생성될 때부터 낮은 점프·높은 점프·지상 유지를 선택합니다. 첫 8단계에는 점프하지 않습니다. 점프 계획은 생성 때 확정하므로 접근 중에 계절이 바뀌어도 갑자기 새 동작을 선택하지 않습니다. 상찌는 위로 넘든 아래로 지나가든 **마리당 10점**을 받으며, 두 마리는 총 20점·세 마리는 총 30점입니다.

추가 상찌는 `sj_run.png`의 2프레임 달리기, 구덩이로 들어가는 `sj_burrow`, 새 `sj_escape.png`로 나오는 `sj_escape`입니다. 구덩이 두 동작은 각각 빠름·느림을 같은 확률로 한 번 선택합니다. 들어가기는 플레이어와 만나기 전에 상찌가 잠기고 구덩이만 남으므로 점프하지 않고 위로 달려 통과할 수 있습니다. 나오기는 네 포즈로 몸을 드러낸 뒤 나온 자세를 유지하며, 몸체를 점프로 넘어갑니다. 구덩이 테두리 자체는 두 경우 모두 충돌하지 않습니다.

같은 이동 속도에서 빠른 진입은 x=480→330, 느린 진입은 480→170 구간에 진행합니다. 빠른 탈출은 480→300, 느린 탈출은 480→180 구간에 진행하며, 모두 플레이어와 닿기 전에 동작을 완료할 여유를 둡니다. 실제 소요 시간은 게임 속도에 따라 달라집니다. 진입은 첫 겨울인 6단계부터, 탈출은 다음 봄인 8단계부터 등장합니다. 뛰어넘거나 안전한 구덩이 위를 달려 지나가도 각각 통과 보너스 10점을 받습니다.

지상의 추가 한성캣·낮은 비행형·지상 또는 낮게 뛰는 상찌는 점프로 피하고, 상·중 비행형·높게 뛰는 한성캣·높게 뛰는 상찌는 아래로 통과합니다. 기본 인사 캐릭터의 점프는 위 표의 패턴에 따라 판단합니다. 날갯짓 지상형·지상의 상찌·달리는 한성캣은 발이 화면 아래로 잘리지 않도록 이미지 하단을 y=358에 맞춥니다. 점프하는 장애물은 각 지상 위치에서 계획한 높이만큼 올라갑니다. 비행형은 머리와의 높이 차이를 보고 지상 유지와 점프를 구분합니다.

첫 봄 낮·밤(0~2단계)에는 손 흔드는 기본 한성냥이·꾸꾸꼬꼬·상찌 세 종류만 등장합니다. 날갯짓 지상형·비행형 네 종류는 첫 여름 낮인 2단계부터, 추가 한성캣 세 종류는 첫 가을 낮인 4단계부터, 달리기·굴 파기 상찌는 첫 겨울 낮인 6단계부터 무작위로 등장합니다. 상찌 무리·랜덤 점프와 구덩이에서 나오는 상찌는 첫 사계절이 끝난 다음 봄인 8단계부터 허용합니다. 한 번 해금된 종류는 이후 모든 계절에도 계속 등장할 수 있습니다. 재시작하면 누적 시간과 등장 조건을 초기화합니다.

기존 지상 전용·비행 혼합 패턴에 추가 한성캣·상찌를 포함한 패턴을 더해 무작위로 선택합니다. 예를 들어 `한성캣 → 상찌`, `흰색 비행형 → 상찌 → 한성캣`처럼 선택된 패턴의 장애물을 차례로 내보냅니다. 상찌 두·세 마리는 한 무리로 출현하고 전체가 사라진 뒤 다음 장애물을 내보내지만, 득점은 각 마리의 통과 시점에 따로 계산합니다. 다음 장애물의 접근 거리는 현재·다가올 슬롯의 속도와 플레이어 점프 시간을 반영합니다. 사이클별 회복 목표는 1.2→1.05→0.9초이며 항상 한 번의 점프·착지 시간에 최소 0.18초의 재입력 여유를 더한 값 이상을 확보합니다. 비행형 바로 아래나 곧바로 뒤에 상찌를 겹쳐 두는 패턴은 없습니다.

## 점수와 난이도

**통과 보너스는 점프 여부와 관계없이 장애물 하나당 10점입니다.** 장애물의 오른쪽 끝이 상상부기의 왼쪽을 완전히 지나면 지급합니다. 비행형과 높은 점프 장애물 아래로 달려 지나가도 같은 10점을 받으며, 장애물 이름·높이·애니메이션 종류나 플레이어의 점프 입력으로 득점을 제한하지 않습니다. 상찌 무리는 각 마리를 별도로 계산합니다.

생존한 온전한 1초마다 1점을 받고 장애물을 통과하면 10점을 추가합니다. 상찌 무리는 각 마리를 지날 때마다 10점을 받습니다. 다른 장애물은 기존처럼 한 장애물 단위당 10점이며, 기본 꾸꾸·꼬꼬의 두 캐릭터 그림도 한 장애물입니다. 위로 넘기와 아래로 통과하기 모두 같은 보너스를 받습니다. 예를 들어 35초 생존하고 상찌 4마리를 통과하면 75점입니다. 먼저 지난 상찌의 점수는 뒤의 상찌와 충돌하더라도 유지하며, 같은 상찌에서 중복 득점하지 않습니다. 일시정지·게임오버 동안 시간과 점수가 멈추고 재시작하면 이번 판 점수·생존 시간·속도가 초기화됩니다. 기존 최고점수 파일은 유지합니다.

난이도는 누적 슬롯과 사계절 사이클로 조절합니다. 배경과 장애물에 같은 속도 배율을 적용하며 점프 속도·중력은 유지합니다.

| 누적 슬롯 | 속도와 패턴 |
| --- | --- |
| 0~7: 첫 사계절 | 슬롯마다 7% 증가, 기본 장애물을 익히는 구간. 점프 장애물 동작은 금지 |
| 8~15: 두 번째 사계절 | 슬롯마다 0.2%만 증가, 접근 간격 감소와 긴 순차 패턴 증가, 점프 장애물 해금 |
| 16+: 세 번째 사계절 이후 | 속도를 약 1.632배로 유지, 어려운 기존 패턴과 연속 순서의 선택 확률 증가 |

첫 7번의 7% 증가와 다음 8번의 0.2% 증가까지만 적용하고, 명시적 속도 상한 `MAX_SPEED_MULTIPLIER=1.75`도 둡니다. 어려운 패턴 풀을 우선 선택할 확률은 사이클별 15%→45%→75%, 선택한 순서를 끝까지 이어가는 확률은 25%→65%→90%입니다. 우선 선택하지 않으면 해금된 전체 풀에서 고릅니다. 첫 사이클에도 이미 해금된 지상·비행 패턴만 후보가 됩니다. 장애물은 앞 단위가 사라진 후 차례로 등장해 겹치는 회피 불가능한 조합을 피합니다.

`config.py`의 `EARLY_SPEED_INCREASE`, `MID_SPEED_INCREASE`, `MAX_SPEED_MULTIPLIER`, `CYCLE_RECOVERY_SECONDS`, `MIN_RECOVERY_TIME`, `HARD_PATTERN_PROBABILITIES`, `PATTERN_CHAIN_PROBABILITIES`에서 난이도를 조절합니다. 생존·통과 점수는 `SURVIVAL_POINTS_PER_SECOND`·`PASS_BONUS`로 관리합니다.

[난이도 보고서](docs/DIFFICULTY_REPORT.json)는 자동 입력으로 확인한 회피 가능성과 연속 플레이의 결과입니다. 사람의 반응 시간·조작감을 대신하는 지표는 아닙니다. 설정을 바꾼 뒤에는 다음 명령으로 다시 생성합니다. 실제 최고점수 대신 임시 파일을 사용합니다.

```powershell
python -B tools/verify_difficulty.py --output docs/DIFFICULTY_REPORT.json
```

2026-11-21 보고서는 현재 `DAY_NIGHT_INTERVAL=5`, `MID_SPEED_INCREASE=0.002` 설정의 결과입니다. 누적 0·2·4·6·7·8·15·16·64슬롯에서 해금된 동작을 따로 고정하고, 120Hz에서 시작 거리 80~400픽셀을 4픽셀 간격으로 탐색했습니다. 337개 슬롯·동작 조합의 27,297회 입력 시뮬레이션에서 각각 회피 가능한 구간이 있었고, 30·60·120FPS의 600초 연속 자동 플레이도 모두 무충돌로 완료했습니다. 마지막 속도는 약 1.631655배였으며 `passed=true`, `failures=[]`를 확인했습니다. 상찌 출발 위치의 무작위 흔들림은 중앙값으로 고정한 검사이므로 모든 무작위 경우를 전수 검사한 결과와는 구분합니다.

## 충돌 판정

실제 출력 크기로 변환한 PNG의 알파값이 `COLLISION_ALPHA_THRESHOLD`보다 큰 픽셀로 마스크를 만듭니다. 투명 픽셀은 충돌하지 않으며, 상상부기의 달리기 4프레임과 점프 때 표시하는 첫 프레임에 맞춰 판정합니다. 장애물은 실제 표시 포즈에 맞는 마스크를 사용합니다. 굴 진입·탈출은 구덩이를 제외한 몸체만 판정하고 완전히 들어간 뒤 남은 구덩이는 안전합니다. 사각형은 빠른 후보 검사에만 사용합니다.

가장자리를 스쳤을 때의 부담을 줄이기 위해 장애물 마스크만 설정 비율만큼 안쪽으로 줄입니다. 현재 설정 6%에서 120픽셀 장애물은 7픽셀, 높이 40픽셀 상찌는 2픽셀, 높이 64픽셀의 굴 파기는 4픽셀입니다. 원본 PNG는 바꾸지 않으며 `config.py`의 `COLLISION_ALPHA_THRESHOLD`, `OBSTACLE_MASK_INSET_RATIO`에서 조절합니다. 마스크는 시작할 때 한 번 생성해 재사용합니다.

검증 내용은 [CHANGELOG](docs/CHANGELOG.md), 구성과 데이터 흐름은 [ARCHITECTURE](docs/ARCHITECTURE.md), 직접 플레이 확인 항목은 [TODO](docs/TODO.md)에 기록합니다.

## Pygame 1.0 이후

Pygame의 480×360 논리 화면과 기본 게임 규칙은 라즈베리파이 이식과 비교를 위한 기준으로 유지합니다. 웹 버전은 별도 프로젝트에서 실제 가로 논리 영역을 넓혀 장애물을 더 일찍 보고 판단할 수 있게 설계합니다. CSS로 화면만 확대하는 방식과 구분하며, 넓어진 화면에 맞춰 생성 위치·이동 시간·등장 템포도 함께 조정합니다. 웹에 맞는 밸런스와 플레이 데이터 수집은 향후 작업입니다.

## 파일 관리 원칙

문서는 docs, 이미지는 image, 실제 최고점수는 `txt/high_score.txt`, 자동 검사는 tests에 둡니다. 기존 학습 TXT 두 개는 STUDY_NOTES로 통합하고, 루트의 계절·날씨·맵 아이디어 노트는 GAME_IDEA로 옮겼습니다.

완료 작업은 CHANGELOG, 미완료 작업은 TODO, 구조 변경은 ARCHITECTURE, 학습 내용은 STUDY_NOTES, 기획과 아이디어는 GAME_IDEA에 적습니다. 경로를 바꾸면 관련 문서 링크도 함께 갱신합니다.
