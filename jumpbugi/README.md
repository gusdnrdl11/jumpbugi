# 점프부기

점프부기는 장애물을 점프로 피하는 Pygame 러너입니다. 기준 폴더는 `jumpbugi/`입니다.

GitHub 저장소는 [개인 jumpbugi](https://github.com/gusdnrdl11/jumpbugi)와 [튜터링 jumpbugi](https://github.com/hansung-tutoring/jumpbugi)이며, 두 저장소의 기본 브랜치는 `main`입니다.

## 실행과 검사

확인 환경은 Python 3.13.15, pygame 2.6.1입니다. jumpbugi 폴더에서 실행합니다.

```powershell
python main.py
python -B -m unittest discover -s tests -v
```

상위 폴더에서는 `python -m jumpbugi.main`으로 실행할 수도 있습니다.

Space: 점프 / Esc: 정지·재개 / 게임오버 후 Enter: 재시작 / Ctrl+F4 또는 창 닫기: 종료

## 첫 실행과 재시작

처음 실행하면 사용자가 확인한 캐릭터 편집본인 `image/start.png`만 2초 동안 보여 줍니다. 잘린 캐릭터와 책을 복원하고 흰 여백을 정리한 이미지이며, 이전 `image/start.jpg`는 참고 원본으로 보존합니다. 이후 흰 배경에서 상상부기가 달리며 ‘점프부기’ 제목과 ‘아무 키나 누르면 시작’ 안내를 표시합니다. 키를 누르면 부기의 위치와 달리기 동작을 그대로 이어 가면서 한성대 봄 낮 배경도 정상 게임의 시작 속도인 초당 420픽셀로 가로 스크롤을 시작합니다. 배경 알파만 1.25초 동안 0에서 255로 높여 흰 배경 위로 움직이는 풍경이 천천히 나타납니다. 부기는 페이드 없이 계속 달리고 제목과 안내는 함께 사라집니다. 시작에 사용한 Space는 점프 입력으로 중복 처리하지 않습니다.

시작 이미지는 실제 캐릭터와 소품이 있는 콘텐츠 영역을 기준으로 희미한 외곽 여백을 제외합니다. 캐릭터가 과하게 잘리지 않도록 작은 안전 여백을 둔 뒤, `object-fit: cover`처럼 비율을 유지해 480×360 화면 전체를 덮고 넘치는 부분만 중앙 기준으로 잘라냅니다. 별도의 제목이나 반투명 테두리를 두지 않습니다. 원본 PNG는 수정하지 않습니다.

시작 이미지·입력 대기·배경 전환 중에는 점수·계절·장애물이 진행되지 않습니다. 배경 전환 중에는 추가 키 입력을 무시하며, 부기의 달리기와 배경 스크롤은 계속됩니다. 전환이 끝나면 배경 위치를 그대로 이어서 플레이를 시작하고 다음 갱신부터 장애물이 화면으로 들어옵니다. 게임오버 후 Enter를 누르면 첫 연출을 생략하고 한성대 봄 낮 배경에서 바로 재시작합니다. 시작 이미지 표시 시간은 `config.SPLASH_SECONDS`, 시작 배경 전환 시간은 `config.START_FADE_SECONDS`에서 조절합니다.

| 단계 | 화면과 진행 |
| --- | --- |
| 첫 이미지 2초 | 제목을 덧그리지 않은 캐릭터 그림이 화면 전체를 채움 |
| 키 입력 대기 | 흰 배경에서 상상부기 달리기, 제목·시작 안내 표시 |
| 시작 전환 1.25초 | 달리는 부기 뒤로 스크롤 중인 배경만 나타나고 제목·안내는 사라짐 |
| 플레이 | 배경 위치와 달리기 자세를 이어받고 장애물·점수·계절 진행 시작 |

캐릭터 파일은 상상부기 `bugi.png`·`bugi_run.png`, 한성캣 `hsucat*.png`, 상찌 `sj*.png`, 치킨 `chicken*.png`로 정리했습니다. 달리기·굴 파기·인사처럼 각 이미지의 동작을 파일명에 표시합니다.

## 계절 배경 순환

배경은 `봄 낮 → 봄 밤 → 여름 낮 → 여름 밤 → 가을 낮 → 가을 밤 → 겨울 낮 → 겨울 밤 → 봄 낮` 순서로 무한 반복합니다.

30초마다 다음 배경으로 전환을 시작하고 기존과 같이 4초 동안 부드럽게 섞습니다. 시작은 봄 낮이며 30초 봄 밤, 60초 여름 낮, 90초 여름 밤, 120초 가을 낮, 150초 가을 밤, 180초 겨울 낮, 210초 겨울 밤, 240초 봄 낮으로 이어집니다. 일시정지·게임오버에서는 전환이 멈추고 재시작하면 봄 낮으로 돌아갑니다.

계절별 낮·밤 PNG 8장은 시작 시 한 번 불러옵니다. 순서는 `config.py`의 `BACKGROUND_FILES`에 있으며 계절이 봄으로 돌아와도 누적 속도와 점수는 유지됩니다.

## 장애물 패턴

상찌·한성캣·기존 꾸꾸까까와 함께 `chicken_flap.png`의 흰색·갈색 캐릭터를 사용합니다. 새 캐릭터는 각각 지상형(높이 96픽셀), 비행형(높이 80픽셀)이 있으며 날갯짓 4프레임과 프레임별 충돌 마스크를 사용합니다.

추가 한성캣은 `hsucat_run.png`의 달리기 4프레임, `hsucat_crouch.png`의 큰 웅크린 모습, `hsucat_book.png`의 한성캣과 책 모습입니다. 달리기 시트는 한 포즈씩 분리해 같은 배율과 발 위치로 정렬합니다. 두 단일 이미지는 원래 구도와 가로세로 비율을 유지합니다. 표시 높이는 120픽셀이며, 두 번째 첨부 이미지인 `hsucat_crouch.png`는 너비 202픽셀로 기존 한성캣의 99픽셀보다 크게 표시합니다.

추가 상찌는 `sj_run.png`의 2프레임 달리기(43×40)와 `sj_dig.png`·`sj_hole.png`를 이용한 12프레임 굴 파기(112×64)입니다. 굴 파기는 땅을 파다가 구멍이 열리고 상찌가 아래로 들어간 뒤 구멍만 남는 순서로 진행합니다. 남은 구멍도 지상 장애물이므로 점프로 피합니다. 첫 겨울부터 기존 상찌가 선택되면 두 마리 또는 세 마리가 무작위로 붙어 등장합니다. 마리 사이 간격은 3픽셀이며 전체 너비는 각각 81·123픽셀입니다. 묶음 하나를 통과하면 10점을 받습니다.

지상형과 추가 한성캣·상찌는 점프로 피하고 비행형은 점프하지 않고 아래로 통과합니다. 날갯짓 지상형과 모든 상찌는 발이 화면 아래로 잘리지 않도록 이미지 하단을 y=358에 맞춥니다. 비행형의 발끝은 서 있는 상상부기 이미지 상단보다 12픽셀 위에 있어 낮은 장애물과 구별됩니다.

첫 봄 낮·밤(0~60초)에는 기존 정지 이미지 세 종류만 등장합니다. 날갯짓 지상형·비행형 네 종류는 첫 여름 낮인 60초부터, 추가 한성캣 세 종류는 첫 가을 낮인 120초부터, 추가 상찌와 두·세 마리 묶음은 첫 겨울 낮인 180초부터 무작위로 등장합니다. 겨울 전에는 기존 상찌가 한 마리씩 등장합니다. 한 번 해금된 종류는 다음 봄(240초 이후)을 포함해 이후 모든 계절에도 계속 등장할 수 있습니다. 재시작하면 누적 시간과 등장 조건을 초기화합니다.

기존 지상 전용·비행 혼합 패턴에 추가 한성캣·상찌를 포함한 패턴을 더해 무작위로 선택합니다. 예를 들어 `한성캣 → 상찌`, `흰색 비행형 → 상찌 → 한성캣`처럼 선택된 패턴의 장애물을 차례로 내보냅니다. 상찌 두·세 마리 묶음도 하나의 장애물 단위이며, 이전 장애물 단위가 완전히 사라진 뒤 다음 단위를 내보냅니다. 속도에 비례해 다음 장애물까지의 접근 거리를 늘려 착지와 다음 판단에 최소 1.2초의 여유를 둡니다. 비행형 바로 아래나 곧바로 뒤에 상찌를 겹쳐 두는 패턴은 없습니다.

## 점수와 난이도

생존한 온전한 1초마다 1점을 받고 장애물을 통과하면 기존과 같이 10점을 추가합니다. 예를 들어 35초 생존하고 4개를 통과하면 75점입니다. 일시정지·게임오버 동안 시간과 점수가 멈추며 재시작하면 이번 판 점수·생존 시간·속도가 초기화됩니다. 기존 최고점수 파일은 유지합니다.

30초마다 낮·밤 배경 전환이 시작될 때 배경과 장애물 속도를 직전의 1.07배로 올립니다. 30초 1.07배, 1분 1.1449배, 3분 1.5007배, 5분 1.9672배이며 상한은 없습니다. 점프 속도와 중력은 유지합니다. `config.py`의 `SURVIVAL_POINTS_PER_SECOND`, `PASS_BONUS`, `SPEED_INCREASE_RATIO`에서 조절합니다.

저장된 [난이도 보고서](docs/DIFFICULTY_REPORT.json)는 이전 설정에서 생성한 기록입니다. 현재 설정으로 다시 확인하려면 다음 명령을 사용합니다. 실제 최고점수 대신 임시 파일을 사용합니다.

```powershell
python -B tools/verify_difficulty.py --output docs/DIFFICULTY_REPORT.json
```

## 충돌 판정

실제 출력 크기로 변환한 PNG의 알파값이 127보다 큰 픽셀로 마스크를 만듭니다. 투명 픽셀은 충돌하지 않으며, 상상부기의 달리기 4프레임과 점프 때 표시하는 첫 프레임에 맞춰 판정합니다. 장애물도 실제 표시 프레임과 같은 마스크를 사용하며 굴 파기 후 남은 구멍 그림에는 충돌 판정이 있습니다. 사각형은 빠른 후보 검사에만 사용합니다.

가장자리를 스쳤을 때의 부담을 줄이기 위해 장애물 마스크만 설정 비율만큼 안쪽으로 줄입니다. 현재 설정 6%에서 120픽셀 장애물은 7픽셀, 높이 40픽셀 상찌는 2픽셀, 높이 64픽셀의 굴 파기는 4픽셀입니다. 원본 PNG는 바꾸지 않으며 `config.py`의 `COLLISION_ALPHA_THRESHOLD`, `OBSTACLE_MASK_INSET_RATIO`에서 조절합니다. 마스크는 시작할 때 한 번 생성해 재사용합니다.

검증 내용은 [CHANGELOG](docs/CHANGELOG.md), 구성과 데이터 흐름은 [ARCHITECTURE](docs/ARCHITECTURE.md), 직접 플레이 확인 항목은 [TODO](docs/TODO.md)에 기록합니다.

## 파일 관리 원칙

문서는 docs, 이미지는 image, 실제 최고점수는 `txt/high_score.txt`, 자동 검사는 tests에 둡니다. 기존 학습 TXT 두 개는 STUDY_NOTES로 통합하고, 루트의 계절·날씨·맵 아이디어 노트는 GAME_IDEA로 옮겼습니다.

AI는 [AGENTS.md](AGENTS.md)의 참조 범위를 따릅니다. 상위 `../study/`, `docs/STUDY_NOTES.md`, `docs/archive/`는 사용자가 명시적으로 요청할 때만 참조합니다. GAME_IDEA와 TODO의 계획은 구현된 기능과 구분합니다. `txt/high_score.txt`는 실행 데이터로 보존합니다. 현재 실행 안내는 이 README와 ARCHITECTURE를 따릅니다.

완료 작업은 CHANGELOG, 미완료 작업은 TODO, 구조 변경은 ARCHITECTURE, 학습 내용은 STUDY_NOTES, 기획과 아이디어는 GAME_IDEA에 적습니다. 경로를 바꾸면 관련 문서 링크도 함께 갱신합니다.
