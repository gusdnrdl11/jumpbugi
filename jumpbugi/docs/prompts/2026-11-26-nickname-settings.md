## 참고 자료의 구현 요구사항 요약

이 절은 첨부 원문의 요약이며, 존재하지 않는 과거 프롬프트를 복원한 기록이 아니다.

- 닉네임은 선택 사항이며 기존 `JumpBugi_XXX` 기본값으로 바로 플레이한다. 최고 기록 영역에 작은 변경 버튼과 저장/취소 편집을 둔다.
- 앞뒤 공백을 정리한 2~12자의 닉네임을 허용하고 빈 값·제어/숨김 문자를 거부한다. 한글·영문·숫자가 가능하고 중복 닉네임을 허용한다.
- UUID·기존 결과·최고점수는 유지한다. localStorage와 players의 현재 이름만 갱신하고 runs의 플레이 당시 이름은 보존한다. 과거 전송 대기열로 현재 이름이 되돌아가지 않게 한다.
- 공동 랭킹은 현재 이름을 표시한다. 브라우저 최고와 서버 제출 기록의 범위를 구분하고 과거 로컬 기록을 삭제하거나 일괄 업로드하지 않는다.
- 기존 색상·간격·PC/모바일 배치·상태별 기록판 위치를 유지한다. 서버 상태는 평상시 간결하게, 실패/미전송 때 상세 안내·재시도를 제공한다.
- 사용자 문자열은 HTML로 삽입하지 않는다. 클라우드·인증·점수 재연산 검증·게임 규칙 변경·대규모 리팩토링은 제외한다.
- 실제 Chrome·Edge·PostgreSQL·자동 검사로 검증하고, 실행하지 않은 검사를 완료로 표시하지 않는다. 비밀번호·연결 문자열은 문서나 Git에 넣지 않는다.

## 검증 기준

기본 이름의 자연 플레이 → 실제 닉네임 변경 → 같은 UUID·기존 기록·점수 확인 → 새로고침 유지 → 서로 다른 브라우저의 같은 이름/다른 UUID 확인 → 과거 이름 결과 재시도 → DB의 현재 이름/과거 이름 직접 SQL 대조 순서다. 빈 값·숨김 문자·편집 취소·HTML 형태 문자 표시와 PC/모바일 배치도 검사한다. 커밋 후보와 실제 인덱스에서 민감정보를 검사한 후 Git 반영한다.
