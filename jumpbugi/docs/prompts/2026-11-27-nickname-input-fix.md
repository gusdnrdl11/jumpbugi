## 최초 요청 원문

줄 끝 공백 표기만 정리했다. 최초 요청은 즉시 착수가 아니라 채팅 기록이었다.

> 현재 닉네임 변경 버튼이 표시되지만 실제 닉네임 입력 및 수정이 불가능한 문제가 발생한다.
>
> 기존 닉네임 UI와 관련 이벤트 처리 코드만 확인하여 수정한다.
>
> **요구사항**
>
> - 게임 시작 전과 게임오버 상태에서 닉네임 변경을 허용한다.
> - 플레이 중, 시작 연출 중, 일시정지 상태에서는 변경을 제한한다.
> - 변경 버튼을 누르면 기존 닉네임 입력란이 활성화되고 직접 수정할 수 있도록 한다.
> - 수정 후 저장 또는 취소할 수 있도록 한다.
> - 닉네임 입력 중 키보드 이벤트가 게임 시작이나 점프 입력으로 전달되지 않도록 한다.
> - 저장 시 localStorage와 서버 DB에 변경된 닉네임을 반영한다.
> - 기존 player_id와 플레이 기록을 유지한다.
> - PC 키보드 및 모바일 터치 입력을 지원한다.
>
> 기존 디자인, 게임 로직, 데이터베이스 구조는 유지한다.
>
> 입력란 활성화 조건, disabled/readonly 속성, 이벤트 리스너 및 게임 상태 처리 충돌 여부를 우선 확인한다.
>
> 수정 후 실제 브라우저에서 닉네임 입력·저장·DB 반영까지 검증한다.
>
> 토큰 절약을 위해 관련 코드만 분석하고 전체 프로젝트 재분석, 문서 정리, 리팩토링, Git commit 및 push는 수행하지 않는다.
>
> 현재 토큰 부족으로 작업은 시작하지마
>
> 내일이나 다른날에 이 내용을 기반으로 수정할거니까
>
> 내용만 채팅에 기록해놔

## 실제 결과

- `ready`·`gameover`에서만 닉네임 변경·입력·저장·취소 컨트롤을 활성화한다. 나머지 상태에서는 비활성화하고 열린 편집 폼을 닫는다. 편집 함수에서도 상태를 확인한다.
- 폼의 키보드 이벤트 전파를 차단하고, 폼이 열린 동안 전역 게임 키 입력을 막는다. 한글 등 IME 조합 중 Enter로 저장되지 않게 한다.
- 기존 localStorage·서버 동기화 경로를 유지한다. 현재 닉네임만 갱신하며 기존 `player_id`·최고점수·과거 결과·대기열의 플레이 당시 닉네임을 보존한다. 게임 로직·DB 구조·디자인은 변경하지 않았다.
- 웹 테스트 45개, 실제 Chrome·Edge 각각 10묶음의 회귀 검증, CDP 터치 이벤트를 이용한 모바일 입력 모사, PostgreSQL 직접 SQL 대조를 통과했다. 모바일 모사는 실제 휴대전화 실기기 검증과 구분한다.
- 로컬 검증 산출물: `web/.qa/local-backend/1795786922341-54540/report.json`, 같은 폴더의 `database-report.json`. Git 제외 경로이며 보고서의 실제 UUID나 DB 연결정보는 이 문서에 옮기지 않는다.

11월 27일 작업에서는 요청에 따라 문서 정리·Git commit·push를 수행하지 않았다. 이 기록의 작성과 두 main 반영은 별도의 [11월 28일 요청](2026-11-28-docs-and-main-sync.md)에 따른다.
