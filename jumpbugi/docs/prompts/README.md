# 개발 프롬프트 관리

개발 과정에서 실제 사용한 요청과 재사용할 양식을 관리합니다. 사용 이력이 확인되지 않은 문장을 과거에 사용한 프롬프트로 만들지 않습니다. 구현·검증 여부는 관련 코드와 실제 결과로 판단합니다.

## 분류와 저장 원칙

분류값은 `기획`, `아키텍처 설계`, `기능 구현`, `테스트·디버깅`, `코드 리뷰`, `리팩토링`, `백엔드 개발`, `배포·운영`을 사용합니다. 빈 분류 폴더를 미리 만들지 않고, 프롬프트 파일의 메타데이터에 분류를 적습니다. 이미지 생성 등 기존 자료는 보조 분류를 덧붙일 수 있습니다.

새 파일은 `YYYY-MM-DD-주제.md`로 작성하고 아래 색인에 추가합니다. 실제 요청 원문, 재사용 템플릿, 기존 설계 자료를 구분합니다. 날짜·작성자·사용 여부가 확인되지 않으면 `미확인`으로 적습니다. 결과물·검증 기준과 실제 검증 결과도 구분합니다.

## 새 프롬프트 작성 양식

아래는 **향후 재사용할 템플릿**이며 과거 사용 기록이 아닙니다.

```markdown
# 작업 제목

- 분류:
- 요청일 / 실제 사용일: (모르면 미확인)
- 출처: (실제 대화, 이슈, 문서 등)
- 상태: 실제 요청 원문 / 재사용 템플릿 / 설계 자료
- 대상 버전·파일:

## 작업 목적
해결할 문제와 기대하는 결과를 적는다.

## 요구사항
필요한 동작과 산출물, 현재 구현과 향후 계획을 구분한다.

## 제한 사항
수정 범위, 유지할 기능·경로·배포 설정, 승인 절차를 적는다.

## 기대 결과물
추가·수정할 문서/파일과 보고 형식을 적는다.

## 검증 기준
실행할 검사, 성공 판단 기준, 환경 제약의 보고 방법을 적는다.

## 실제 결과
작업 후에만 실제 변경과 검사 결과·남은 문제를 기록하거나 CHANGELOG로 연결한다.
```

## 민감정보와 기록 보존

API 키, 비밀번호, 토큰, 인증 파일, 실제 사용자 식별정보를 원문·예시·결과에 넣지 않습니다. 필요한 값은 `<API_KEY>` 같은 자리표시자로 적고 비밀 값 자체는 별도로 관리합니다. 환경변수 파일을 Git에서 제외해도 이미 추적 중인 비밀정보가 제거되는 것은 아니므로 변경 diff도 확인합니다.

과거 원문을 편집해 당시 요구사항을 바꾸지 않습니다. 현재 경로 안내·상태·추가 승인은 원문 밖의 메타데이터로 적고, 미확인 정보와 실행하지 않은 검사를 완료로 기록하지 않습니다.
