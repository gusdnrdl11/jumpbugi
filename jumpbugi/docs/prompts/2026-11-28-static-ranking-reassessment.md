## 선행 요청과 작업 흐름 요약

아래는 대화와 실제 작업의 요약이며 사용자 요청 원문을 재구성한 인용문이 아니다. 임시 변경의 검사 결과와 최종 유지된 기능을 구분한다.

1. 사용자는 로컬 서버 모드에서는 정상인데 GitHub Pages에서는 닉네임이 여러 행에서 함께 바뀐다고 보고하고, 먼저 수정 없이 원인을 확인하도록 요청했다. 코드 검토에서는 저장된 과거 이름이 유지되며, 정적 기록판이 같은 UUID의 여러 플레이 결과를 현재 이름으로 표시한다는 모드 차이를 설명했다.
2. 정적 웹과 Pages의 문제를 수정해 달라는 후속 요청에서 표시 의미를 확인했다. 사용자는 **사용자별 최고 기록 1행과 현재 닉네임을 표시하고 UUID·과거 결과·플레이 당시 이름은 보존하는 2번 대안**을 선택했다.
3. 정적 랭킹 조회에서만 UUID별 최고 1행을 선택하는 임시안을 관련 네 파일에 적용했다. 원본 결과 저장과 서버 공동 랭킹·오류 시 브라우저 기록 표시 동작은 유지하는 범위였다.
4. 임시안에서는 웹 단위 테스트 47개, 정적 Chrome·Edge 각각 11묶음, 서버 Chrome·Edge 각각 10묶음의 검증을 통과했다. 이는 당시 대안의 동작 확인이며 기존 코드가 잘못됐다는 증거나 원복 후 최종 코드의 신규 검사 결과로 취급하지 않는다.
5. 사용자가 `http://127.0.0.1:8000/`에서 같은 이름의 다섯 행이 남는다고 다시 보고했다. 후속 브라우저 실행 승인은 거절되어 진단 범위로 제한했다. 현재 서버가 제공하는 파일과 기존 탭의 실행 코드·저장 데이터는 별개라는 점을 검토했으며, 캐시를 실제 원인으로 확정하지 않았다.
6. 사용자는 최근 변경 요청을 취소하고 웹 배포판과 같다면 수정이 필요 없다는 뜻을 밝혔다. 개인 GitHub Pages의 공개 `app.js`를 HTTP 200으로 읽었고, 해당 파일의 SHA-256이 main의 같은 파일과 일치함을 확인했다. 튜터링 Pages의 같은 형식 주소는 HTTP 404였으므로 해당 웹 배포 상태를 확인했다고 기록하지 않는다. Git의 두 main 상태 확인은 웹 배포 확인과 별개다.
7. 후속 유지 요청에 따라 임시 네 파일을 `f2fa6d4` 상태로 원복했다. 원복 직후 코드 변경이 남지 않은 Git 상태를 확인했으며, 이 문서 최신화는 그 이후 별도로 승인된 작업이다.

## 반복 작업과 재판단 기록

초기 원인 보고에서도 과거 저장값 유지와 현재 이름 표시 치환을 구분했다. 다만 정상적인 모드 차이와 사용자가 바꾸려는 표시 요구를 충분히 구분하지 못해 같은 주제의 임시 수정·검증을 반복했다. 2번 선택을 받은 뒤 대안을 작성했으나, 후속 배포판 유지 요청에 따라 다시 판단하여 폐기했다. 이 임시안을 현재 기능의 완료 항목으로 남기지 않는다.

현재 유지한 동작은 다음과 같다.

- 정적 웹·GitHub Pages·로컬의 쿼리 없는 접속은 브라우저에 보관된 플레이 결과 중 상위 5행을 표시한다. 현재 브라우저 identity와 같은 UUID의 여러 판은 현재 이름으로 함께 표시하며 각 판의 시간·점수는 유지한다. 다른 UUID의 닉네임에는 적용하지 않는다.
- 저장된 과거 결과의 플레이 당시 닉네임과 UUID는 보존된다. 표시 이름이 함께 바뀌는 것과 과거 저장값의 일괄 수정은 구분한다.
- 로컬의 `?server=1` 공동 랭킹은 사용자별 최고 기록 1행과 현재 닉네임을 표시한다. 정적 랭킹의 UUID별 1행 임시 기능은 원복되어 현재 구현에 포함되지 않는다.
- 브라우저 QA 프로필·보고서·스크린샷은 `web/.qa/`의 Git 제외 산출물이다. 보고서의 실제 UUID, DB 비밀번호·연결 문자열은 문서나 커밋에 옮기지 않는다.
