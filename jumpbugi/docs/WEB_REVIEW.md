# Web 0.1 구조와 점검 기록

점검 기준일: **2026-11-22 (한국 시간)**. 현재 실행 코드·테스트·실행 자산을 기준으로 정리했다. 설계 지침은 이식 의도를, TODO는 미완료 작업을 나타낸다. 과거 연습 코드·학습 노트·보관 문서는 현재 실행의 근거로 사용하지 않았다.

## 현재 구현

Pygame과 웹은 실행 경로가 분리되어 있다. Python은 `main.py → backend.py / frontend.py`로 실행하고, 웹은 `index.html → src/app.js → engine.js / storage.js`로 실행한다. 웹의 `serve.py`는 정적 파일만 전달하며 게임 규칙이나 결과를 처리하지 않는다. 웹 실행에 Pygame·npm 의존성 설치는 필요 없다.

| 영역 | 구현 위치와 점검 내용 |
| --- | --- |
| 게임 규칙 | `engine.js`의 `GameEngine`: 물리·마스크 충돌·득점·장애물 선택과 동작·계절·난이도 |
| 화면과 입력 | `app.js`: 자산 선로딩, Canvas 출력, 키보드·터치, 시작 연출, 정지·재시작, 결과 저장 연결 |
| 브라우저 기록 | `storage.js`의 `PlayerStore`: 독립 ID·임시 닉네임·결과 최대 50개·상위 5개·예시 표시 |
| 화면 배치 | HTML의 고정 게임·HUD·기록판 컨테이너와 CSS의 PC 두 열·좁은 화면 한 열 |
| 실행 자산 | `assets/manifest.json`의 PNG 경로·크기·프레임별 충돌 마스크와 `assets/`의 이미지 |
| 자산 재생산 | `tools/export_assets.py`: 현재 Python 자원 조립 결과를 `web/assets/`에만 내보내기 |
| 개발 검사 | Node 내장 테스트와 `tools/browser-smoke.mjs`의 설치된 Chrome/Edge 검사 |

논리 화면은 Pygame 480×360, 웹 640×360이다. 웹 부기의 x좌표는 `RULES.playerX=25`이며 표시 배율과 무관한 논리 좌표다. 두 버전의 낮·밤 슬롯은 현재 25초, 사계절 8슬롯은 200초, 배경 혼합은 4초다. Python의 설정을 수정해도 JavaScript 설정은 자동 갱신되지 않는다.

이 역할 구분과 아래 검사 범위에서 명확한 기능 오류를 발견하지 못해 기존 웹 게임 소스를 유지했다. 문서의 미구현 웹 설명과 오래된 검사 기준을 바로잡고 현재 구현·학습 경로·검증 결과를 정리했다.

웹의 화면 단계는 `loading → splash(2초) → ready(입력 대기) → transition(1.25초) → playing → gameover`다. 일시정지는 별도 화면 단계가 아니라 `engine.paused`다. 시작 입력은 점프로 중복 사용하지 않고, 게임오버는 Enter 또는 다시 시작 버튼으로 새 판을 시작한다. 웹의 `ready`는 인트로 그림 전체를 유지하므로 Pygame의 흰 배경 달리기 대기와 다르다.

## 이번 브라우저 검사

Python 3.13.15, pygame 2.6.1, Node v24.19.0과 Windows에 설치된 Chrome으로 검사했다. 임시 서버는 `127.0.0.1:8765`에서 웹 폴더만 제공했다.

```powershell
# jumpbugi 폴더에서 별도 터미널로 실행
python -B web/serve.py --port 8765

# jumpbugi/web 폴더에서 실행
node tools/browser-smoke.mjs http://127.0.0.1:8765/
```

브라우저 검사 결과는 **통과**, 콘솔·런타임 오류는 **0개**였다.

- PC 1440×1000, 모바일 세로 390×844와 가로 844×390에서 화면 넘침과 주요 배치를 검사했다.
- 인트로 전체 표시·2초 뒤 입력 대기 유지·대기 중 점수/장애물 정지·시작 입력의 점프 중복 방지를 확인했다.
- Space 점프, Esc 정지·재개, 정지 중 시간 고정, 터치 시작·점프를 확인했다.
- 게임오버 메시지, 이동·애니메이션·시간·점수 정지, Space/Esc로 종료 상태가 재개되지 않음을 확인했다.
- 게임오버 결과 1회 저장, Enter/아이콘 재시작, 새로고침 후 ID·기록 보존을 확인했다.
- 시작 대기·전환·플레이·정지·게임오버·재시작에서 같은 기록판 DOM과 위치를 유지하고, 모바일에서 게임→SCORE/TIME→기록판 순서를 유지하는지 검사했다.
- 상단 일시정지 버튼이 숨김·비활성 상태인지 확인했다. 정지는 Esc와 화면 이탈 자동 정지를 사용한다.
- PC·모바일 세로 화면 캡처를 직접 열어 게임·점수 줄·기록판의 배치도 확인했다.

화면 캡처와 상세 JSON은 로컬 `web/.qa/`에 저장한다. 브라우저 프로필·캐시·화면은 Git에서 제외하고 결과 요약은 이 문서에 남긴다. 브라우저 검사는 전용 임시 프로필을 사용해 실제 브라우저의 게임 기록을 건드리지 않는다.

## Python 회귀 검사와 HTTP 실행

```powershell
# jumpbugi 폴더
python -B -m unittest discover -s tests -v
```

전체 **146개 검사 통과**, 230.618초, 종료 코드 0을 확인했다. 물리·충돌·득점·계절·해금·장애물 동작·시작 연출·저장과 검증 도구 검사를 포함한다. 테스트는 임시 점수 경로를 사용한다.

첫 샌드박스 실행은 Windows 임시 폴더 정리 권한(`WinError 5`) 때문에 실패했다. 정상 권한으로 같은 전체 명령을 다시 실행한 위 결과를 최종 판단에 사용했다. 이 문제를 게임 코드 오류로 처리하지 않았다.

로컬 서버에서 HTML·세 JavaScript 모듈·manifest·favicon의 HTTP 200 응답과 올바른 Content-Type, `no-cache`, `nosniff` 헤더를 확인했다. 브라우저가 이 자산으로 정상 실행되는 것도 위 흐름 검사로 확인했다.

## 실행 자산 대조

SDL dummy 환경에서 현재 `assets.load_game_assets()`가 만든 결과와 `web/assets/`를 읽기 전용으로 대조했다. 원본 소스·실제로 로드한 원본 이미지·웹 자산의 검사 전후 해시가 같았으며, 자산을 다시 내보내거나 덮어쓰지 않았다.

| 대상 | 결과 |
| --- | --- |
| 배경 8장·플레이어 4프레임·장애물 15종 70프레임·인트로 | PNG 총 83개 크기·RGBA 픽셀 일치 |
| 준비된 배경·캐릭터 PNG | 82개를 같은 방식으로 재인코딩한 바이트도 일치 |
| 인트로 | 실제 원본 PNG 바이트와 일치 |
| 충돌 마스크 | 플레이어·장애물 74개의 크기·행 데이터 전체 일치 |
| manifest 경로 | 참조 PNG 83개, 누락 0개, 미참조 PNG 0개 |

따라서 현재 커밋에 포함하는 웹 자산은 현재 Python 자원 조립 결과와 일치한다. 원본 이미지의 보관 여부만으로 실행 사용 여부를 추정하지 않고 실제 로더와 manifest로 확인했다.

[DIFFICULTY_REPORT.json](DIFFICULTY_REPORT.json)을 2026-11-22의 **25초 슬롯** 설정으로 다시 생성했다. `passed=true`, `failures=[]`, 종료 코드 0이다. 누적 0·2·4·6·7·8·15·16·64슬롯에서 해금된 동작을 고정하고 120Hz·시작 거리 80~400픽셀·4픽셀 간격으로 탐색했다. 337개 슬롯·계획 조합의 총 27,297회 입력 시뮬레이션에서 각각 회피 가능한 구간을 확인했다.

| 연속 자동 플레이 | 생존 | 점수 | 생존 점수 + 통과 보너스 | 통과 장애물 단위 |
| --- | --- | --- | --- | --- |
| 30FPS | 600초, 무충돌 | 6,240 | 600 + 5,640 | 425 |
| 60FPS | 600초, 무충돌 | 6,240 | 600 + 5,640 | 425 |

마지막 속도는 모두 약 1.631655배였다. 상찌 무리는 구성원별로 점수를 주므로 장애물 단위 수에 10을 곱한 값과 통과 보너스는 다르다. 프레임별 장애물 교체 시점 차이로 최종 점수와 통과 수에 작은 차이가 있다.

이 보고서는 **Pygame 기준본의 자동 입력 검사**다. 웹 엔진의 장시간 연속 플레이 검사로 해석하지 않는다. 웹은 위 21개 테스트에서 실제 내보낸 마스크로 장애물 회피와 여러 프레임 속도의 기본 물리를 검사했다. 자동 회피 탐색은 이산 입력 표본이며 상찌 출발 흔들림은 12.5픽셀 중앙값으로 고정한다. 사람의 반응 시간·실제 조작감이나 모든 무작위 상황을 검증한 결과와 구분한다.

## 확인 범위와 남은 작업

모바일 검사는 Chrome의 화면·터치 모사다. 실제 휴대폰의 성능·터치감, 사람이 느끼는 난이도와 장시간 플레이 재미는 별도 사용자 테스트가 필요하다. 웹의 실제 온라인 공동 랭킹·서버 DB와 인터넷 서비스 배포는 구현 범위에 포함되지 않는다.

긴 프레임 지연에서 경과 시간·생존 점수는 전체 시간차를 적용하고 이동은 최대 0.1초만 따라간다. 탭·창 이탈은 자동 정지하지만 실제 기기에서의 장시간 성능 저하와 밸런스는 별도로 관찰해야 한다.

웹 기록은 브라우저의 같은 출처(프로토콜·호스트·포트)별 `localStorage`에 보관한다. 주소·포트·브라우저를 바꾸면 다른 기록이 보일 수 있으며 Pygame의 `txt/high_score.txt`와는 독립적이다. 검사와 학습을 위해 기존 점수 파일이나 사용자 기록을 초기화하지 않았다.
