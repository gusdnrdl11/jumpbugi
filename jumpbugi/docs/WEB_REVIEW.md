# Web 0.1 구조와 점검 기록

최신 구현·회귀 검사 기준일: **2026-11-27 (한국 시간)**, 문서 대조일: **2026-11-28**. 2026-11-22의 이식·2026-11-25의 문서 정리 기록은 아래에 날짜를 유지해 보존한다. 현재는 선택적 로컬 FastAPI·PostgreSQL 연결을 포함하며 실행 코드·테스트·실행 자산을 기준으로 설명한다. 설계 지침·TODO의 향후 기능을 구현으로 간주하지 않는다.

## 현재 구현

Pygame과 웹은 실행 경로가 분리되어 있다. Python은 `desktop_prototype/main.py → backend.py / frontend.py`로 같은 폴더의 모듈을 호출하고, 웹은 `web/index.html → src/app.js → engine.js / storage.js`로 실행한다. 웹의 `serve.py`는 정적 파일만 전달하며 게임 규칙이나 결과를 처리하지 않는다. 웹 실행에 Pygame·npm 의존성 설치는 필요 없다.

| 영역 | 구현 위치와 점검 내용 |
| --- | --- |
| 게임 규칙 | `engine.js`의 `GameEngine`: 물리·마스크 충돌·득점·장애물 선택과 동작·계절·난이도 |
| 화면과 입력 | `app.js`: 자산 선로딩, Canvas 출력, 키보드·터치, 시작 연출, 정지·재시작, 결과 저장 연결 |
| 브라우저 기록 | `storage.js`의 `PlayerStore`: 독립 ID·닉네임 설정·결과 최대 50개·플레이 결과 상위 5개·예시 표시 |
| 선택적 서버 동기화 | `api.js`의 `LocalServerSync`: loopback `?server=1`, 신규 결과 전송·최대 50개 대기열·동일 ID 재시도·공동 기록판 |
| 로컬 API·DB | `server/main.py`, `schema.sql`, `local.py`: FastAPI·요청별 트랜잭션·PostgreSQL players/runs·loopback 실행 |
| 화면 배치 | HTML의 고정 게임·HUD·기록판 컨테이너와 CSS의 PC 두 열·좁은 화면 한 열 |
| 실행 자산 | `assets/manifest.json`의 PNG 경로·크기·프레임별 충돌 마스크와 `assets/`의 이미지 |
| 자산 재생산 | `web/tools/export_assets.py`: `desktop_prototype.assets`의 자원 조립 결과를 `web/assets/`에만 내보내기 |
| 개발 검사 | Node 내장 테스트와 `tools/browser-smoke.mjs`의 설치된 Chrome/Edge 검사 |

논리 화면은 Pygame 480×360, 웹 640×360이다. 웹 부기의 x좌표는 `RULES.playerX=25`이며 표시 배율과 무관한 논리 좌표다. 두 버전의 낮·밤 슬롯은 현재 25초, 사계절 8슬롯은 200초, 배경 혼합은 4초다. Python의 설정을 수정해도 JavaScript 설정은 자동 갱신되지 않는다.

게임 엔진·물리·마스크·자산·브라우저 저장 키와 결과 형식은 유지했다. `app.js`에는 기존 로컬 저장 후 비동기 전송·상태 표시와 닉네임 설정을 연결하고 `api.js`를 추가했다. 기본 Pages/정적 모드에서는 API 요청이 없으며 별도 백엔드 없이 계속 실행된다.

웹의 화면 단계는 `loading → splash(2초) → ready(입력 대기) → transition(1.25초) → playing → gameover`다. 일시정지는 별도 화면 단계가 아니라 `engine.paused`다. 시작 입력은 점프로 중복 사용하지 않고, 게임오버는 Enter 또는 다시 시작 버튼으로 새 판을 시작한다. 웹의 `ready`는 인트로 그림 전체를 유지하므로 Pygame의 흰 배경 달리기 대기와 다르다.

닉네임 편집은 `ready`·`gameover`에서만 허용한다. `refreshUI()`가 변경 버튼·입력란·저장·취소의 `disabled`를 맞추고 다른 단계로 넘어가면 편집기를 닫는다. `editNickname()`·`saveNickname()`도 상태를 확인하므로 강제 이벤트로 제한을 우회하지 못한다. 폼의 키보드 전파 차단과 전역 처리의 폼 열림 확인으로 편집 중 게임 입력을 막으며, 한글 조합 중 Enter는 저장하지 않는다.

정적 모드·Pages는 로컬 플레이 결과 상위 5개를 표시하므로 같은 사용자의 여러 판이 함께 나올 수 있다. `renderLeaderboard()`는 현재 identity와 ID가 같은 행을 현재 닉네임으로 표시하며, 원본 결과의 당시 이름·점수·UUID는 바꾸지 않는다. 다른 ID의 이름은 그대로다. 서버 모드는 조회가 성공한 공동 목록에 한해 사용자별 최고 결과 한 행과 `players`의 현재 이름을 표시한다. 서버 조회 전·실패 시의 로컬 대체 목록도 플레이 결과 단위다.

### 정적 배포와 향후 서버의 경계

개발자가 제공한 배포 현황에 따르면 웹 버전은 GitHub Pages로 배포되어 있다. 저장소 루트 `pygame/`의 [`.github/workflows/deploy.yml`](../../.github/workflows/deploy.yml)에서도 `./jumpbugi/web`를 Pages 산출물로 업로드하도록 설정되어 있다. 공개 JavaScript 파일의 응답 대조는 아래 2026-11-28 기록에서 범위와 결과를 구분한다. 원격 Actions의 실행 성공 이력은 확인하지 않았으며 워크플로와 배포 경로는 변경하지 않는다.

Pages는 HTML·CSS·JavaScript·이미지·manifest를 제공하는 정적 호스팅이다. 로컬 FastAPI·PostgreSQL은 별도 `server/`에서 실행하며 같은 출처의 `/?server=1`로만 선택한다. Pages에서 로컬 DB에 자동 접속하지 않는다. `web/serve.py`는 기존 정적 개발 서버로 유지하며 API 서버가 아니다. 클라우드 운영·사용자 인증·게임 재연산을 통한 서버 점수 검증은 미구현이다. `docs/`는 Pages 산출물에 포함되지 않는다.

## 2026-11-26 로컬 서버 연결 검증

실제 PostgreSQL API 검사 9개와 웹 검사 34개가 통과했다. 웹 검사에는 원래 21개와 전송·대기열·재시도·native fetch 수신 객체 회귀 검사 13개가 포함된다. Chrome 157.0.8103.79·Edge 158.0.4370.33을 실제 실행파일의 새 격리 프로필로 구동해 자연 게임오버 → 각각 다른 UUID 사용자 → DB 저장 응답 → 공동 기록판 → 동일 프로필 재접속을 확인했다. 동일 결과 재전송은 중복을 만들지 않고 변경된 결과는 409, 음수 점수는 422였다.

## 확인 범위와 남은 작업

모바일 검사는 Chrome·Edge의 화면·터치 모사다. 실제 휴대폰의 성능·터치감, 사람이 느끼는 난이도와 장시간 플레이 재미는 별도 사용자 테스트가 필요하다. loopback의 공동 랭킹·서버 DB는 구현되어 있으며, GitHub Pages의 정적 게임 배포와 별개인 공개 API·DB 서버 운영은 향후 개발 범위다.
