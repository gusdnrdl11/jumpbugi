# 한성런 현재 구조

## 폴더 지도

```text

├─ README.md            실행 안내와 문서 목차

├─ main.py              실행·입력·반복 순서
├─ frontend.py          화면과 UI
├─ backend.py           상태와 게임 규칙
├─ config.py            공통 설정과 내부 경로
├─ assets.py            이미지 준비
├─ storage.py           최고점수 읽기·저장
├─ __init__.py          패키지 표시
├─ docs/
│  ├─ TODO.md
│  ├─ CHANGELOG.md

```

`__pycache__`는 파이썬이 만드는 캐시입니다. 현재 게임은 상위 폴더의 image·txt·테스트·실행 래퍼 없이 실행할 수 있습니다.

이 문서는 현재 한성런의 구조를 설명합니다. 공부하면서 배운 개념은 [STUDY_NOTES](STUDY_NOTES.md), 게임 기획과 아이디어는 [GAME_IDEA](GAME_IDEA.md)에 모읍니다. 선택한 다음 작업은 [TODO](TODO.md), 완료 기록은 [CHANGELOG](CHANGELOG.md)에 둡니다.

## 역할과 연결

```text
main → frontend → assets
main → backend → storage
main / frontend / backend / assets → config
tests → 게임 동작 확인
```

메인·프론트·백은 같은 프로그램입니다. 백은 인터넷 서버가 아니라 게임 규칙 담당입니다. `HansungRun`이 화면 담당 `GameView`와 상태 담당 `GameState`를 보유합니다.

메인은 화면을 먼저 만들고 이미지 크기·모션 수·배경 너비·프레임별 플레이어 마스크·종류별 장애물 마스크를 백에 전달합니다. 백은 위치와 마스크 겹침으로 충돌을 계산하며 화면을 만들거나 이미지를 읽지 않습니다. 프론트는 백의 상태와 공통 `player_frame_index`를 사용해 같은 프레임을 그립니다.

assets는 그림 읽기·크기 조절·모션 시트 분리와 합성을 맡습니다. storage는 파일을 읽고 임시 파일 교체 방식으로 기록합니다. config는 여러 파일이 공유하는 기준표입니다. 보조 작업을 꺼내면 화면 코드와 규칙 코드를 찾고 수정하기 쉽습니다.

## 실행 순서

`main() → pygame 초기화 → HansungRun 생성 → run() → 종료 시 pygame 정리`

run은 경과 시간 확인 → 입력 처리 → 백 갱신 → 화면 출력 순서로 반복합니다. `game_over`는 이번 판의 종료, `running=False`는 실행 반복 자체의 종료입니다. 정지·게임오버 동안 일반 갱신은 멈춥니다.

## 경로 기준

`config.PROJECT_DIR = Path(__file__).resolve().parent`입니다. config.py가 있는 hansungrun 폴더가 기준이며 터미널의 현재 위치와 무관합니다.

- 이미지: `PROJECT_DIR / 'image'`
- 최고점수: `PROJECT_DIR / 'txt' / 'high_score.txt'`
- 프로젝트를 다른 곳으로 옮길 때도 이 폴더들을 함께 옮깁니다.

## 현재 사양과 저장

480×360, 출력 목표 120FPS, 물리 수치 기준 60Hz입니다. 점프 속도 -15, 중력 0.6, 통과 보너스 10점입니다. 기존 장애물, 흰색·갈색 캐릭터의 지상·비행형, 추가 한성캣, 상찌의 달리기·굴 파기·두 마리·세 마리 묶음을 무작위 순차 패턴으로 사용합니다. 한성부기의 달리기는 네 프레임이며 계절별 낮·밤 8장이 30초 간격에 3초 혼합으로 순환합니다.

생존 점수는 `survival_elapsed`의 온전한 1초마다 1점씩 더합니다. 통과 보너스와 합산하며 정지·게임오버 때는 갱신하지 않습니다. 시간은 실제 전달된 양수 dt를 누적하고, 기존과 같이 물리 이동만 0.1초로 제한합니다. 충돌이 발견된 갱신까지의 생존 점수가 최고점수에 반영됩니다.

속도 배율은 `1.05 ** floor(background_elapsed / 30)`입니다. 전환 시작인 30·60·90초에 증가하며 3초간의 배경 혼합 완료 시점까지 기다리지 않습니다. 배경과 장애물에 동일한 배율을 적용하고 점프 물리는 유지합니다. 가속 후에도 물리 세부 단계에서 장애물 이동량은 최대 6픽셀이 되도록 계산 간격을 줄입니다. 재시작하면 생존 시간과 배경 시계가 모두 0이 되어 기본 속도로 돌아갑니다.

신기록은 게임오버 또는 종료 요청 시 저장합니다. 기록이 없으면 0으로 시작하지만 숫자가 아닌 내용이나 음수 기록을 자동 복구하지는 않습니다.

## 장애물 유형과 패턴

`OBSTACLE_FILES`는 기존 정지 이미지 3개, `CHICKEN_TYPES`는 추가된 흰색·갈색 지상형과 비행형 4개입니다. `assets.load_chicken_frames`는 `ggoggoandgguggu_side.png`의 2행×4열을 캐릭터별로 분리하고 동일한 크기·발 위치로 정렬합니다. 시트는 시작 시 한 번 읽으며 지상형은 높이 96, 비행형은 80입니다.

`HANSUNGCAT_TYPES`는 `hansungcat_2.png`, `hansungcat_3.png`, `hansungcat_4.png`입니다. 첫 파일의 2×2 시트는 네 달리기 포즈로 분리한 뒤 공통 배율과 발 위치로 정렬합니다. 나머지 두 파일은 구도와 가로세로 비율을 유지한 단일 이미지입니다. 추가 한성캣의 표시 높이는 120이며, 의도적으로 큰 두 번째 첨부 이미지인 `hansungcat_3.png`는 202×120으로 기존 한성캣의 99×120보다 넓습니다. `hansungcat_4.png`는 한성캣과 책을 함께 포함한 180×120 이미지입니다. 원본 PNG는 수정하지 않습니다.

`SANGJJI_TYPES`는 `sangjji_2.png`, `sangjji_burrow`, `sangjji_pair`, `sangjji_triple`입니다. `sangjji_2.png`의 1행×2열 시트는 43×40의 달리기 두 포즈로 나눕니다. 굴 파기는 `sangjji_3.png`의 1행×2열 시트와 `sangjji_4.png`의 구멍을 112×64의 공통 크기인 12프레임으로 합성합니다. 땅 파기 → 구멍 열림 → 상찌가 아래로 내려감 → 구멍만 남음 순서이며, 접근 x좌표가 480에서 180으로 이동하는 구간에서 진행합니다. 마지막 구멍은 화면 밖으로 나갈 때까지 유지되고 지상 장애물로 충돌하므로 점프해야 합니다.

기존 상찌 한 마리는 39×40입니다. 겨울 해금 뒤 자동 생성에서 기본 상찌가 선택되면 두 마리 또는 세 마리 묶음으로 무작위 변환합니다. 마리 사이 3픽셀을 두고 합성해 두 마리의 크기는 81×40, 세 마리는 123×40입니다. 묶음은 단일 장애물과 하나의 충돌 마스크로 처리하며 전체가 통과했을 때 보너스 10점을 한 번만 더합니다. 원본 PNG는 수정하지 않습니다.

프론트는 `obstacle_frames`와 포즈별 `obstacle_frame_masks`를 준비해 백에 전달합니다. 백의 `obstacle_frame_index`를 출력·충돌에 함께 사용하고 정지·게임오버에서는 애니메이션도 멈춥니다. 정지 이미지의 마스크는 기존 단일 마스크를 사용합니다.

시작 장애물은 기존 정지 이미지 3종 중 하나입니다. 첫 봄 낮·밤(0~60초)에는 `CHICKEN_TYPES`, `HANSUNGCAT_TYPES`, `SANGJJI_TYPES`를 패턴 후보와 대기열에서 모두 제외합니다. 따라서 `GROUND_PATTERNS` 중 기존 이미지로만 구성된 순서만 선택합니다. 날갯짓 지상·비행형은 첫 여름 낮인 60초부터, 추가 한성캣은 첫 가을 낮인 120초부터, 추가 상찌와 두·세 마리 묶음은 첫 겨울 낮인 180초부터 허용합니다. 해금 시간은 각각 `CHICKEN_UNLOCK_SECONDS`, `HANSUNGCAT_UNLOCK_SECONDS`, `SANGJJI_UNLOCK_SECONDS`로 정하며, 겨울 전 기본 상찌는 한 마리씩 유지합니다. 조건은 누적 시간에만 적용하므로 다음 봄(240초 이후)을 포함해 이후 모든 계절에도 해금된 종류가 계속 등장할 수 있습니다. 재시작하면 누적 시간과 대기열을 초기화해 등장 조건을 복원합니다.

날갯짓 지상형의 y좌표는 `SCREEN_SIZE[1] - obstacle_height + CHICKEN_GROUND_OFFSET`입니다. `CHICKEN_GROUND_OFFSET=-2`를 적용해 이미지 하단을 y=358로 맞추므로 360픽셀 화면 안에서 네 프레임의 발 전체가 보입니다. 일반 지상 장애물의 `OBSTACLE_GROUND_OFFSET=7`보다 9픽셀 위에 배치하며 비행형의 위치는 변경하지 않습니다.

기존 상찌와 추가 상찌·묶음·굴 파기도 하단을 y=358에 맞춥니다. `SANGJJI_GROUND_OFFSET=-2`를 사용하므로 기존 상찌 위치보다 9픽셀 올라가 발이 화면 아래로 잘리지 않습니다. 굴 파기는 상태가 바뀌어도 112×64 크기와 하단 위치를 유지합니다.

비행형의 y좌표는 `ground_y - FLYING_HEAD_GAP - obstacle_height`입니다. 현재 발끝 y=230으로 서 있는 플레이어 이미지 상단 y=242보다 12픽셀 위에 배치하므로 모든 지상 자세에서 아래로 통과할 수 있습니다. 점프하면 날갯짓 마스크와 겹쳐 충돌할 수 있습니다.

장애물은 항상 한 단위씩만 활성화하며 상찌 두·세 마리 묶음도 한 단위입니다. 전체 이미지가 화면 왼쪽으로 완전히 나간 뒤 다음 장애물을 생성합니다. 새 x좌표는 `max(480, player_width + 현재 초당 이동속도 × 1.05 × 1.2초)`로 정해 다음 5% 가속을 고려한 접근 여유를 둡니다. 이전 장애물이 사라진 뒤 다음 장애물 왼쪽이 플레이어 이미지 오른쪽에 도달하기까지 최소 1.2초를 확보합니다. 점프 시간 약 0.82초보다 길어 지상→비행, 비행→상찌 등에서도 회피 준비가 가능합니다. 이 시간에는 화면 밖에서 접근하는 구간도 포함되며, 화면에 보인 뒤의 반응 시간과 같지는 않습니다.

## 계절 배경

`config.BACKGROUND_FILES`의 순서는 봄 낮·밤, 여름 낮·밤, 가을 낮·밤, 겨울 낮·밤입니다. `background_elapsed`로 누적 전환 횟수를 계산하고 이미지 인덱스만 8로 나눈 나머지를 사용합니다. 240초에 겨울 밤에서 봄 낮으로 돌아가며 시계와 속도 배율은 초기화하지 않습니다.

백은 `background_from_index`, `background_to_index`, `background_alpha`로 이전·다음 배경과 3초 전환 혼합도를 관리합니다. `night_alpha`는 점수 글자색의 낮·밤 밝기 계산용으로 유지합니다. 프론트는 시작할 때 준비한 `background_stages` 8장을 같은 출력 크기·스크롤 위치에서 합성합니다.

`sync_background(state)`는 배경 인덱스 두 개와 혼합도를 함께 캐시합니다. 같은 알파값이더라도 다른 계절이면 다시 그리며, 공용 오버레이 표면에 대상 배경을 복사해 원본 이미지를 변경하지 않습니다. 정지·게임오버 중에는 그대로 유지하고 재시작 시 봄 낮을 즉시 복원합니다.

## 마스크 충돌

`assets.collision_mask`는 최종 출력 크기의 알파값이 127보다 큰 픽셀을 사용합니다. `frontend`가 플레이어 4프레임과 기존 장애물·새 캐릭터의 포즈별 마스크를 시작 시 한 번 준비합니다. 기존 사이드 이미지는 프레임 크기·정렬 기준으로 유지하며 충돌 윤곽에는 실제 달리기 프레임을 사용합니다.

장애물은 높이의 설정 비율(최소 1픽셀)만큼 8방향으로 테두리를 깎습니다. 현재 설정 6%에서 높이 120의 장애물은 7픽셀, 높이 40의 상찌는 2픽셀, 높이 64의 굴 파기는 4픽셀입니다. 투명 여백을 채우거나 사각형으로 축소하지 않으므로 실제 윤곽 안쪽에 판정이 남습니다. 굴 파기의 마지막 구멍도 표시 프레임의 마스크로 충돌하며, 플레이어 마스크는 줄이지 않습니다.

백은 사각형으로 후보를 거른 뒤 마스크 겹침으로 게임오버를 결정합니다. `int()`로 변환한 동일한 출력 좌표와 프레임 번호를 렌더링·충돌 양쪽에 사용합니다. 픽셀 검사는 물리 갱신 시점의 위치에서 수행하며 연속 궤적 전체를 검사하는 방식은 아닙니다.

| `test_game.py` | 입력·반복 실행, 점프·착지, 출력·애니메이션과 백의 독립 동작 |
| `test_collision.py` | 알파 마스크·윤곽 완화, 실제 픽셀 충돌, 게임오버·재시작과 출력 좌표 |

| `test_hansungcat_obstacles.py` | 추가 한성캣의 가을 해금·크기·달리기·충돌과 회피 |
| `test_sangjji_obstacles.py` | 겨울 상찌·밀집 묶음·굴 파기·화면 안 배치와 회피 |
| `test_scoring_speed.py` | 생존 점수·통과 보너스·저장과 누적 가속 |

기존 `test_game09.py`에 섞여 있던 검사는 역할에 맞는 파일로 옮겼습니다. 마스크 검사는 `test_collision.py`로 이름을 바꿨으며 기존 검사 내용을 유지합니다. 테스트의 공통 초기화가 다른 클래스는 같은 파일에서도 분리해 둡니다.

`test_seasons.py`는 계절별 자산 순서, 두 바퀴의 16개 전환 직전·정각·중간·완료 시점의 실제 픽셀, 겨울→봄 순환 시 속도 유지, 같은 혼합도의 다른 계절 캐시, 큰 dt·정지·재시작, 초기화 후 이미지 재로딩 없이 화면 출력을 검사합니다.

`test_scoring_speed.py`는 초 경계·통과 보너스 합산·정지·재시작·저장·30초 가속 경계·FPS별 점수를 검사합니다. `tools/verify_difficulty.py`는 실제 이미지로 0~10분의 21단계에서 장애물별 시작 거리를 80~400픽셀, 2픽셀 간격으로 탐색하고 고정 난수 시드로 연속 자동 플레이합니다. 지상형에는 점프, 비행형에는 지상 유지를 적용하며 포즈별 마스크를 사용합니다. [JSON 결과](DIFFICULTY_REPORT.json)의 구간은 이 탐색 범위 안에서의 결과이며 사람의 반응 시간을 나타내지 않습니다. 연속 플레이는 Space 키 이벤트를 넣고 프레임마다 물리를 갱신하며 1초마다 및 게임오버 시 화면을 출력합니다.

`test_obstacle_patterns.py`는 두 캐릭터의 4프레임, 첫 봄의 날갯짓 4유형 제외·대기열 제거·60초 해금·240초 이후 봄 허용, 모든 날갯짓·달리기 프레임 조합의 지상 통과와 점프 충돌을 검사합니다. 날갯짓 지상형은 네 프레임의 발 전체가 화면 안에 들어오는지도 검사합니다. 첫 60초의 1,200번 무작위 생성도 기존 정지 이미지만 사용하는지 확인합니다. 기존 지상·비행 혼합 패턴을 4단계 속도(60초·120초·300초·600초)와 3가지 FPS에서 실제 키 입력으로 회피하고, 장애물 교체 시 접근 간격·득점도 확인합니다.

`test_hansungcat_obstacles.py`는 추가 한성캣의 첫 봄·여름 제외와 120초의 가을 해금, 이후 겨울·봄의 유지, 해금 전 대기열 제거와 재시작, 무작위 선택 후보, 달리기 프레임별 마스크, 큰 이미지의 비율 보존, 충돌과 FPS별 점프 회피를 검사합니다. 세 종류×4단계 속도(120초·180초·300초·600초)×3가지 FPS(30·60·120)의 36개 조합에서 점프로 통과하는지 확인합니다.

`test_sangjji_obstacles.py`의 13개 테스트는 상찌의 겨울 해금과 다음 봄 유지, 해금 전 제외와 재시작, 달리기 프레임·굴 파기 진행·마지막 구멍 유지, 두·세 마리 묶음과 단일 통과 보너스, 화면 안의 발 위치와 점프 회피를 검사합니다. 새 상찌 4종×4단계 속도(180초·240초·300초·600초)×3가지 FPS(30·60·120)의 48개 조합에서 한 번의 점프로 통과하는지 확인합니다.

`python -B -m unittest discover -s tests -v`로 `tests/`를 검사합니다. 파일 재배치 후에도 겨울 상찌를 포함한 전체 63개 테스트가 통과했습니다. 난이도 보고서에서는 장애물 14종 모두 21단계 속도에서 회피 가능한 구간을 확인했습니다. 키 입력·렌더링을 포함한 무작위 자동 플레이는 30·60·120FPS에서 각각 10분 생존했습니다. `test_collision.py`는 장애물 14종의 첫 포즈를 포함한 실제 이미지 2,352가지 배치를 독립적인 알파 픽셀 비교와 대조하고 테두리 접촉·게임오버·점프 회피·출력 좌표를 검사합니다. 테스트는 별도 임시 점수 파일을 사용합니다. 실제 창의 외관과 조작감은 직접 플레이로 확인합니다.
