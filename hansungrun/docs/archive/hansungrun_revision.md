# 2. 한성런 수정 내역 및 게임 검토

검토 기준: 2026-11-07. 현재 코드의 정적 검토와 직전 자동 검사 결과를 구분한다. 아래 제안은 이번 문서 작업에서 게임 코드에 적용하지 않았다.

## 구조 평가

입력·상태 계산·출력이 분리되어 있고 초기화는 `reset()`을 공유한다. 자원 재사용과 최고점수 경로 주입으로 검사와 유지보수가 용이하다. 현재 규모에 적절하다.

다만 `HansungRun`이 자원·입력·물리·저장·화면을 모두 담당한다. 지금 즉시 분리할 필요는 없지만 시작 화면이나 동시 장애물 도입 시 책임을 나누는 편이 좋다.

## 수정 검토: 우선순위 1

### 모션의 시각적 일관성

`load_run_frames()`는 각 포즈의 전체 여백을 제거하고 발을 기준으로 배치한다. 동일 배율이어도 포즈별 머리·몸통 위치나 그림 비율까지 고정되지는 않는다. 현재는 포즈 전체를 사용하며 상체를 합성해 고정하지 않는다.

프레임 간 상체 흔들림이 생길 가능성이 있어 실제 재생 확인이 필요하다. 필요하면 몸통 기준점과 프레임별 배치 보정을 사용한다. 완료 기준은 0→1→2→3→0 전환에서 머리가 갑자기 튀지 않고 착지 전환도 자연스러운 것이다.

### 지면과 충돌 영역

기준 플레이어 표면 아래끝은 y=362, 장애물 표면 아래끝은 y=367이며 화면 높이는 360이다. 표면 일부가 화면 아래에 놓인다. 실제 발 위치는 PNG의 투명 여백에 따라 달라지므로 좌표만으로 그림이 잘린다고 단정할 수 없다.

충돌은 불투명 픽셀이 아닌 전체 표면을 축소한 사각형이다. 모션과 관계없이 기준 `player_image` 크기를 사용한다. 공통 지면을 정하고 개발용 충돌 상자를 표시해 세 장애물의 지상 충돌·점프 회피를 비교하는 것을 권장한다. 완료 기준은 발 위치와 지면이 일치하고 충돌 시점이 그림과 어울리는 것이다.

### 기록 파일 오류 대응

`load_high_score()`는 파일 없음만 처리한다. 빈 파일·문자·음수는 예외로 시작을 중단한다. 쓰기·교체 실패도 그대로 전달되어 게임이나 정상 종료가 중단될 수 있다. 임시 파일 교체가 모든 저장 실패를 처리하는 것은 아니다.

잘못된 원본을 보존하면서 기본 점수로 실행할지 정책을 정하고 저장 실패 안내를 추가하는 방향을 권장한다. 완료 기준은 파일 없음·내용 손상·쓰기 실패 각각에서 정해진 동작을 하고 기존 정상 기록을 잃지 않는 것이다.

## 수정 검토: 우선순위 2

### 게임오버와 정지 입력

ESC가 게임오버 검사보다 먼저 처리되어 게임오버에서도 정지를 켤 수 있다. 이때 Enter가 무시되어 재시작 안내와 동작이 어긋날 수 있다. 게임오버에서 ESC를 무시하거나 Enter가 정지를 해제하고 재시작하도록 규칙을 정리한다.

완료 기준은 어떤 순서로 ESC·Enter를 눌러도 안내와 실제 동작이 일치하는 것이다.

### 착지·재등장의 시간 경계

착지는 갱신 단계 끝에서 보정하며 장애물 이탈 시 x=480으로 초기화한다. 경계를 지난 남은 시간·이동량은 별도로 적용하지 않는다. 배경 반복의 이동량은 보존한다.

경계 부근에서 60Hz·120Hz 결과가 조금 달라질 수 있다. 기존 시간 비교 검사는 점프 초반 구간이므로 전체 착지·재등장의 동일성을 보장하지 않는다. 전체 점프와 여러 재등장을 다른 dt로 비교하고, 문제가 관찰되면 남은 시간 처리나 고정 시간 단계 누적을 검토한다.

## 수정 검토: 우선순위 3

- 재시작 문구 `press the Enter Restart`를 읽기 쉽게 정리한다.
- 매우 큰 점수에서는 HUD가 화면을 넘을 수 있으므로 표시 범위를 정한다. 현재 검사는 999999점까지다.
- 테스트 파일 첫 설명의 명령도 현재 프로젝트 루트 기준 명령으로 정리할 필요가 있다.
- 이전 미리보기와 공부 노트는 현재 코드와 다를 수 있어 교육 자료로 사용할 때 별도 갱신한다.
