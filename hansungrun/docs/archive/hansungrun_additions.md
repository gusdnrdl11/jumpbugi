# 3. 한성런 추가 기능 제안

작성: 2026-11-07. 아래 항목은 현재 코드에 없는 제안이며 구현 완료를 뜻하지 않는다. 기존 동작 개선은 [수정 문서](hansungrun_revision.md)를 우선한다.

## 기능과 적용 순서

| 순서 | 제안 | 목적 | 구현 접점 | 완료 기준 |
| --- | --- | --- | --- | --- |
| 1 | 시작 화면·조작 안내 | 시작 전 조작 학습 | 입력·출력·상태 관리 | 시작 입력 전 이동·점수 정지 |
| 2 | 효과음·음소거 | 점프·득점·충돌 피드백 | 자원 로딩과 각 이벤트 | 이벤트당 한 번 재생, 음소거 가능 |
| 3 | 등장 간격 변화 | 반복 리듬 완화 | 장애물 생성·갱신 | 회피 가능한 최소 간격 보장 |
| 4 | 점수별 난이도 | 생존 시간에 따른 도전 | 속도·갱신·초기화 | 상한을 두고 증가, 재시작 시 복원 |
| 5 | 밤 배경·스테이지 | 진행에 따른 시각 변화 | 배경 로딩·전환·출력 | 전환 시 빈 화면·좌표 튐 없음 |
| 6 | 코인 등 수집 요소 | 회피 외 선택과 보상 | 별도 개체·충돌·출력 | 중복 획득 차단, 점수 규칙 명확화 |
| 7 | 여러 장애물 동시 등장 | 다양한 패턴 구성 | 장애물 객체 목록 | 이동·득점·제거를 독립 처리 |

## 구현 전에 정할 규칙

- 속도와 등장 빈도 중 무엇으로 난이도를 높일지 정한다. 동시에 크게 올리면 회피 불가능한 배치가 생길 수 있다.
- 점프 비행 시간·장애물 폭·속도를 고려해 최소 간격을 정한다. 무작위화만으로 회피 가능성을 보장하지 않는다.
- 밤 배경이 그림만 바꾸는지 게임 규칙도 바꾸는지 정한다.
- 수집 점수를 통과 점수와 합산할지 별도 표시할지 정한다.
- 키보드 전용 조작을 유지할지 정한다.

## 확장 시 구조 제안

현재는 단일 클래스 구성을 유지해도 충분하다. 기능이 늘어날 때 다음 책임을 점진적으로 분리한다.

| 구성 | 책임 | 분리 시점 |
| --- | --- | --- |
| 설정 | 화면·물리·난이도 수치 | 스테이지별 설정 도입 |
| Player | 점프·착지·모션·충돌 영역 | 플레이어 동작 증가 |
| Obstacle | 종류·좌표·이동·통과 상태 | 동시 장애물 도입 |
| 장면 상태 | 시작·플레이·정지·게임오버 전환 | 시작 화면 도입 |
| 기록 저장 | 읽기·검증·저장·오류 처리 | 기록 정책 확장 |
| HansungRun | 입력 전달·진행·출력 순서 조정 | 위 책임을 점진적으로 위임 |

## 권장 개발 단계

1. 모션·지면·충돌·기록 오류를 먼저 정리한다.
2. 시작 안내와 효과음으로 기본 피드백을 완성한다.
3. 등장 간격과 난이도를 각각 조정하며 실제 플레이로 회피 가능성을 확인한다.
4. 결과에 따라 배경 전환·수집 요소·동시 장애물을 선택한다.

구현을 마치면 기획 문서에 확정 규칙을 반영하고 수정 문서에 변경·검증 결과를 기록한다. 이 문서에는 남은 제안을 유지한다.
