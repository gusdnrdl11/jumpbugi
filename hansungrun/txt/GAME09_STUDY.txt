1. 어떤 게임인가요?

한성부기가 장애물을 점프로 피하는 게임이에요.
장애물을 완전히 지나치면 10점을 받아요.
부딪히면 게임오버예요. Enter를 누르면 다시 시작해요.

캐릭터는 화면 왼쪽에 있어요. 가로 위치는 x=0으로 고정돼 있어요.
대신 배경과 장애물이 왼쪽으로 움직여요.
그래서 캐릭터가 앞으로 달리는 것처럼 보여요.
현재는 시작 메뉴 없이 실행하자마자 게임이 시작돼요.


2. 실행과 조작

프로젝트 폴더의 터미널에서 실행해요.

python prototype_game.py

Space: 점프
Enter: 게임오버 후 새 판 시작
ESC: 잠깐 멈추기 / 다시 움직이기
Ctrl+F4 또는 창 닫기: 최고점수를 반영하고 종료

ESC는 종료 버튼이 아니에요.
잠깐 멈춘 동안에는 Space와 Enter가 동작하지 않아요.


3. 게임이 일하는 순서

게임은 아주 빠르게 그림을 바꾸는 그림책과 비슷해요.
하지만 그림만 바꾸는 것이 아니라 위치와 점수도 계산해요.

준비하기
  ↓
시간 재기 → 키 확인 → 위치·충돌·점수 계산 → 화면 그리기
  ↑                                             ↓
  └──────────────── 다시 반복 ──────────────────┘

이 반복을 담당하는 함수가 run()이에요.

handle_events(): 무엇을 눌렀나요?
update(dt): 시간이 흐른 만큼 무엇이 바뀌나요?
draw(): 지금 상태를 어떻게 보여 줄까요?

입력, 계산, 그리기를 나누어 놓아서 고칠 곳을 찾기 쉬워요.


4. 변수와 설정

변수는 값을 기억하는 이름표예요.

self.score = 0
# 이번 판 점수라는 이름표에 0을 적어요.

self.score += 10
# 기존 점수에 10을 더해요.

게임 위쪽에는 자주 조절하는 값을 모아 두었어요.

SCREEN_SIZE = (480, 360)   창의 가로 480, 세로 360
FPS = 120                1초에 최대 약 120번 그리는 것을 목표로 해요.
PHYSICS_HZ = 60          움직임 계산의 기준은 1초에 60칸이에요.
CHARACTER_HEIGHT = 120   기준 캐릭터 그림의 높이예요.
OBSTACLE_SPEED = 6       기준 시간 한 칸에 장애물이 6픽셀 가요.
JUMP_SPEED = -15         점프를 시작할 때 위로 향하는 속도예요.
GRAVITY = 0.6            아래로 끌어당기는 정도예요.
PASS_BONUS = 10          장애물 하나를 통과하면 받는 점수예요.
RUN_FRAME_TICKS = 6      기준 시간 6칸 동안 한 포즈를 보여 줘요.

픽셀은 화면을 이루는 작은 점이에요.
큰 영어 글자로 쓴 설정 이름은 '설정값이에요'라는 약속이에요.
파이썬이 변경을 막아 주는 것은 아니에요.

자주 보는 기호도 알아둘까요?
=    오른쪽 값을 왼쪽 이름에 저장해요.
==   두 값이 같은지 물어요.
+=   원래 값에 더해요.
-=   원래 값에서 빼요.
//   나눈 뒤 정수 몫을 구해요. 120 // 3은 40이에요.
%    나머지를 구해요. 순서를 반복할 때도 써요.
True / False   맞아요 / 아니에요를 나타내요.


5. 화면의 주소 x, y

왼쪽 위가 (0, 0)이에요.
x가 커지면 오른쪽으로, y가 커지면 아래로 가요.

(0, 0) ─────────→ x 증가
  │
  │
  ↓ y 증가

그림 위치는 보통 그림을 둘러싼 사각형의 왼쪽 위예요.

self.obstacle_x -= OBSTACLE_SPEED * step
# x에서 이동 거리를 빼므로 장애물이 왼쪽으로 가요.

self.ground_y = 360 - 120 + 2
# 결과는 242예요. 지상에 있을 때 플레이어 표면의 위쪽 y예요.

ground_y라는 이름이 있지만 발바닥의 y 자체는 아니에요.
실제 발 위치에는 그림 높이와 투명 여백도 영향을 줘요.


6. 함수, 클래스, self

함수는 여러 일을 묶은 작은 작업 상자예요.
load_image()는 '그림 읽기와 크기 맞추기 상자'예요.
reset()은 '새 판 준비 상자'예요.

클래스는 물건을 만드는 설계도라고 생각해 보세요.
class HansungRun은 게임 상자의 설계도예요.
HansungRun()을 실행하면 실제 게임 상자가 만들어져요.

self는 '지금 이 게임 상자'를 뜻해요.
self.score는 이 게임의 점수,
self.player_y는 이 게임의 캐릭터 세로 위치예요.

__init__()는 게임 상자가 만들어질 때 준비하는 함수예요.
화면, 그림, 글꼴, 기록을 준비하고 reset()으로 첫 판을 시작해요.


7. 그림 파일을 찾고 크기 맞추기: load_image()

from pathlib import Path
import random

Path는 파일 주소를 다루는 도구예요.
random은 제비뽑기처럼 무작위로 고르는 도구예요.
pygame은 창, 그림, 키 입력 등을 다루는 도구예요.

IMAGE_DIR = Path(__file__).resolve().parent / 'image'

이 코드는 'prototype_game.py가 있는 폴더 안의 image 폴더'를 찾아요.

load_image('sangsangbugi_side.png', height=120)

가로도 같은 비율로 조절해서 그림이 납작해지지 않게 해요.

convert(): 현재 배경을 불투명하게 만들어 사용해요.
배경이 이전 화면과 섞이는 문제를 줄이기 위한 처리예요.


8. 처음 한 번 준비하는 일

__init__()는 화면 크기와 제목을 정하고 시계를 만들어요.
배경, 캐릭터, 네 포즈, 세 종류 장애물을 미리 읽어요.
점수 글꼴과 게임오버·일시정지 안내도 준비해요.
최고점수를 읽고 첫 판을 시작해요.

장애물이 다시 나올 때마다 파일을 새로 읽지는 않아요.
이미 준비한 그림 중 하나를 골라 써요.
매번 책을 다시 사지 않고 책장에서 꺼내 읽는 것과 비슷해요.


9. FPS와 시간: 빨리 그려도 게임이 빨라지지 않는 이유

FPS는 1초에 화면을 몇 번 그리는지 나타내요.
현재 목표는 120FPS예요. 컴퓨터 상황에 따라 실제 값은 낮을 수 있어요.

dt = self.clock.tick(FPS) / 1000.0

시계가 알려 준 밀리초를 1000으로 나누어 초로 바꿔요.
dt는 '지난번 이후 몇 초가 흘렀나요?'라는 값이에요.

현재 게임은 화면 한 장마다 무조건 6픽셀을 움직이지 않아요.
흐른 시간에 맞춰 이동 거리를 계산해요.

60FPS라면 약 1/60초가 흘러요. 기준 시간 1칸이므로 약 6픽셀 가요.
120FPS라면 약 1/120초가 흘러요. 기준 시간 반 칸이므로 약 3픽셀 가요.

6 × 60 = 360
3 × 120 = 360

어느 경우든 정상적으로 진행하면 1초에 약 360픽셀 가요.
FPS=120과 PHYSICS_HZ=60은 역할이 달라요.
하나는 그리기 목표, 다른 하나는 움직임 수치의 기준이에요.


10. 시간을 작게 나누기: update()와 update_step()

update(dt)는 먼저 게임오버나 일시정지인지 확인해요.
맞으면 return으로 계산을 끝내요.

너무 긴 시간이 한꺼번에 들어오면 최대 0.1초만 반영해요.
예를 들어 창을 옮기다가 오래 멈춰도 바로 멀리 순간이동하지 않게 해요.
대신 이때는 실제로 흐른 시간 전체를 따라잡지 않아요.

그다음 시간을 기준 시간 칸으로 바꿔요.
0.05초 × 60 = 3칸이에요.
이 경우 한 번에 3칸을 뛰지 않고 최대 1칸씩 세 번 계산해요.

step은 '이번에는 기준 시간 몇 칸만큼 계산하나요?'예요.
step=1이면 1/60초, step=0.5이면 1/120초에 해당해요.

작게 나누면 장애물을 건너뛰어 충돌을 놓칠 위험을 줄일 수 있어요.
아주 작은 계산 찌꺼기를 끝없이 반복하지 않도록 1e-9라는 작은 기준도 써요.

update_step()의 순서:
배경 이동 → 달리기 시간 → 점프 → 장애물 이동
→ 충돌 검사 → 통과 점수 → 다음 장애물


11. 배경 두 장으로 계속 달리기

배경은 높이 360에 맞춰 읽고 같은 그림을 두 곳에 그려요.
첫 그림은 background_x에,
둘째 그림은 background_x + background_width에 그려요.

[긴 배경 A][같은 긴 배경 B]
       ← 함께 왼쪽으로 이동

한 장이 빠져나가는 동안 다음 장이 빈 곳을 채워요.
파일을 두 번 읽는 것이 아니라 같은 그림을 두 번 그리는 거예요.

background_x 계산의 %는 이동 거리를 배경 길이 안에서 반복하게 해요.
끝을 넘은 거리도 남겨서 이어 움직여요.
장애물과 배경의 속도는 같아요.
게임오버나 일시정지에서는 배경도 멈춰요.


12. 네 장의 그림으로 달리기: load_run_frames()

현재 사용하는 파일은 image/sangsangbugi_run_4frames.png예요.
다른 옛 모션 파일이 폴더에 있어도 현재 이 함수는 이 파일을 읽어요.

시트는 포즈 여러 개를 한 장에 모아 둔 그림이에요.
현재 시트는 다음처럼 두 줄, 두 칸이에요.

[0번 포즈][1번 포즈]
[2번 포즈][3번 포즈]

for row in range(2)는 두 줄을 살펴봐요.
그 안의 for col in range(2)는 각 줄의 두 칸을 살펴봐요.
그래서 0 → 1 → 2 → 3 순서로 꺼내요.

subsurface(): 큰 그림에서 필요한 부분을 꺼내요.
get_bounding_rect(min_alpha=20): 거의 투명한 곳을 제외한 그림 영역을 찾아요.
copy(): 꺼낸 그림을 따로 복사해요.
append(): 준비한 목록 뒤에 하나 더 넣어요.

각 포즈의 빈 테두리를 정리하고 모두 같은 배율로 줄여요.
기준 캐릭터 영역의 가로 중심과 발바닥에 맞춰 올려요.
현재는 머리부터 다리까지 포즈 전체를 사용해요.
상체를 첫 그림으로 고정하고 다리만 붙이는 방식은 아니에요.

RUN_FRAME_TICKS = 6

기준 시간 6칸 = 6/60초 = 0.1초 동안 한 포즈를 보여 줘요.
실제 화면을 반드시 6번 그린다는 뜻은 아니에요.
120FPS라면 한 포즈가 대략 화면 12장 동안 보여요.

0번 → 1번 → 2번 → 3번 → 다시 0번
한 바퀴는 0.4초예요.

animation_tick은 달리기 시간이 얼마나 지났는지 기억해요.
이 값을 6으로 나눈 몫으로 보여 줄 포즈 번호를 골라요.
%로 시간이 일정 범위에서 반복되게 하므로 번호가 끝없이 커지지 않아요.

점프 중: 첫 포즈를 그리고 달리기 시간은 멈춰요.
착지 후: 멈추기 전 달리기 시간에서 이어가요.
게임오버·일시정지: 계산이 멈추므로 포즈도 그대로예요.

같은 배율과 발 정렬이 그림 속 머리 위치까지 같게 만드는 것은 아니에요.
자연스러움은 실제로 재생하면서 확인해야 해요.


13. 점프와 착지

Space를 누르면 먼저 '이미 점프 중인가요?'를 확인해요.
아니라면 다음 값을 바꿔요.

self.velocity_y = JUMP_SPEED
self.is_jumping = True

velocity_y는 세로로 움직이는 속도예요.
처음에는 -15예요. y가 작아지면 위로 가므로 음수로 시작해요.
중력은 시간이 흐를수록 속도를 아래쪽으로 바꿔요.

기준 시간 한 칸마다 속도는 다음처럼 바뀌어요.
-15 → -14.4 → -13.8 → … → 0 근처 → 양수

음수일 때는 올라가고, 양수가 되면 내려와요.
실제 코드는 step을 곱해서 반 칸이면 그만큼만 변화시켜요.

위치를 계산할 때 쓰는 식:
self.player_y += self.velocity_y * step + GRAVITY * step * (step + 1) / 2

긴 식을 지금 외울 필요는 없어요.
'현재 속도로 이동한 거리와 중력이 더한 거리를 합친다'고 읽으세요.
기준 시간 한 칸씩 계산하던 움직임에 맞추면서,
더 작은 시간으로 나누어도 비슷한 궤적을 만들기 위한 식이에요.

내려오다가 player_y가 ground_y 이상이면 지상 위치에 맞춰요.
속도를 0으로 하고 is_jumping을 False로 돌려요.
그래서 바닥 아래로 계속 떨어지지 않고 다시 점프할 수 있어요.


14. 장애물 뽑기와 작은 상찌

spawn_obstacle()은 다음 장애물을 준비해요.

random.choice(OBSTACLE_FILES)
# 세 이름 중 하나를 제비뽑기해요.

한성캣: 높이 120
꼬꼬와 꾸꾸: 높이 120
상찌: 높이 40

OBSTACLE_HEIGHTS는 이름별 키를 적어 놓은 표예요.
이처럼 이름과 값을 짝지은 자료를 딕셔너리라고 불러요.

상찌의 높이는 120 // 3 = 40이에요.
가로도 비율에 맞춰 줄어요. 현재 이미지에서는 39픽셀이에요.
그림 파일 자체를 작게 덮어쓰는 것이 아니라 게임 안에서 줄여 써요.

작은 장애물을 큰 장애물과 같은 위쪽 위치에 두면 공중에 떠 보여요.
그래서 키에 맞춰 위쪽 위치를 계산해요.

obstacle_y = 360 - 그림 높이 + 7
큰 장애물: 247
작은 상찌: 327
두 표면의 아래끝: 367

7은 위치를 조정하는 보정값이에요.
화면 높이 360보다 아래끝이 조금 낮아요.
실제 발이 보이는 위치는 투명 여백도 함께 봐야 해요.

장애물은 한 번에 한 개만 나와요.
왼쪽으로 완전히 사라지면 새 종류를 골라 오른쪽 x=480에 놓아요.
같은 종류가 연속해서 나올 수도 있어요.
현재는 별도 대기 시간이나 점수별 속도 증가가 없어요.


15. 부딪힘 검사

게임은 그림을 둘러싼 사각형을 만들어요.
get_rect()는 그 사각형을 구하는 도구예요.
부딪힘 검사에 쓰는 사각형을 히트박스라고 불러요.

플레이어는 전체 가로·세로를 각각 40씩 줄여요.
큰 장애물은 전체 가로를 50, 세로를 35 줄여요.

inflate(-50, -35)
# 양쪽에서 각각 50을 빼는 뜻이 아니에요.
# 전체 가로가 50 줄고 중심은 그대로예요.

작은 상찌에는 줄이는 수치도 크기에 맞춰 작게 적용해요.
큰 수치를 그대로 빼서 사각형 폭이 음수가 되는 일을 피하려는 거예요.

player_hitbox.colliderect(obstacle_hitbox)
# 두 검사 상자가 겹치나요?

겹치면 game_over를 True로 하고 최고점수를 반영해요.
그 단계의 나머지 계산은 return으로 끝내요.

매 포즈마다 충돌 상자를 바꾸지는 않아요.
기준 player_image로 같은 크기의 상자를 사용해요.
그림의 불투명한 픽셀끼리 정밀 비교하는 방식은 아니에요.


16. 점수를 한 번만 받기

장애물 사각형의 오른쪽 끝이 플레이어 왼쪽을 완전히 지나면 득점해요.
이때 축소한 충돌 상자가 아니라 전체 그림 사각형을 기준으로 해요.

self.score += PASS_BONUS
self.passed = True

passed는 '이 장애물의 점수를 이미 받았나요?'라는 메모예요.
이 메모가 없으면 같은 장애물을 지나친 뒤에도 계속 점수를 받을 수 있어요.
새 장애물을 만들면 passed를 False로 바꿔요.

SCORE: 이번 판 점수
BEST: 지금까지 확정해서 보관한 최고점수

현재 점수는 오른쪽 끝, 최고점수는 그 왼쪽에 놓아요.
글자의 폭을 계산해서 점수가 길어져도 오른쪽 끝을 맞춰요.


17. 최고점수 저장

변수는 프로그램이 끝나면 사라져요.
기록을 다음 실행에도 보려면 파일에 적어 두어야 해요.
현재는 코드 파일 옆의 high_score.txt를 써요.

load_high_score(): 파일을 읽고 글자를 숫자로 바꿔요.
파일이 없으면 첫 실행으로 보고 0을 돌려줘요.

record_high_score(): 이번 점수가 더 클 때만 기록을 바꿔요.

예를 들어 BEST가 30이고 SCORE가 40이어도,
플레이 중에는 BEST가 계속 30으로 보일 수 있어요.
부딪히거나 프로그램을 종료할 때 40으로 확정해요.
ESC 일시정지만으로는 저장하지 않아요.

저장 순서:
high_score.tmp에 먼저 적기 → 다 적으면 high_score.txt로 교체하기

기존 기록을 쓰다 중간에 잘라 버릴 위험을 줄이는 방법이에요.
모든 오류를 없애 주는 것은 아니에요.
파일에 글자나 음수가 들어 있거나 쓰기 권한이 없으면 현재 코드는 오류가 날 수 있어요.
정상 기록을 임의로 지워서 복구하는 코드는 없어요.


18. 일시정지와 게임오버

paused는 '잠깐 멈췄나요?'라는 메모예요.

self.paused = not self.paused

not은 반대로 바꿔요.
False면 True, True면 False가 되어서 ESC로 정지·재개를 번갈아 해요.

정지하면 배경, 장애물, 점프, 모션, 점수 계산이 멈춰요.
화면은 계속 그려서 어두운 덮개와 PAUSED 안내를 보여 줘요.
창 닫기와 종료 입력은 계속 받아요.

game_over는 '이번 판이 끝났나요?'라는 별도 메모예요.
현재 코드는 게임오버에서도 ESC로 정지를 켤 수 있어요.
그 상태에서는 Enter가 무시돼요.
다시 ESC로 정지를 풀고 Enter를 눌러야 재시작해요.
이 부분은 앞으로 조작 규칙을 더 쉽게 정리할 수 있어요.


19. 새 판과 프로그램 종료

reset()은 새 판 준비예요.

캐릭터를 지상으로 → 점프 속도 0 → 새 장애물 선택
→ 모션·배경 위치 초기화 → 점수 0 → 게임오버·정지 해제

최고점수와 이미 읽어 둔 그림은 지우지 않아요.
처음 시작할 때와 Enter 재시작 때 같은 함수를 사용해요.

stop()은 현재 기록을 반영하고 running을 False로 바꿔요.
run()은 이 값을 보고 반복을 끝내요.

main()은 pygame.init()으로 준비하고 게임을 실행해요.
finally의 pygame.quit()는 실행 중 오류가 나더라도 정리를 시도해요.

if __name__ == '__main__':
    main()

이 파일을 직접 실행했을 때만 게임을 켜라는 뜻이에요.
검사 코드가 prototype_game을 불러오기만 할 때 게임 루프가 시작되지 않게 해요.


20. 화면에 그리는 순서: draw()

그림을 나중에 그리면 앞의 그림 위에 올라와요.
스티커를 차례대로 붙이는 것과 같아요.

1) 배경 두 장
2) 장애물
3) 현재 플레이어 포즈
4) BEST와 SCORE
5) 게임오버라면 게임오버·재시작 안내
6) 일시정지라면 어두운 덮개와 정지 안내
7) pygame.display.flip()으로 완성된 화면 보여 주기

blit()는 그림을 다른 화면에 올리는 도구예요.
font.render()는 글자를 그림처럼 만들어 주는 도구예요.
Surface는 그림을 올릴 수 있는 도화지라고 생각하면 돼요.


21. 함수별 찾아보기

그림 크기를 바꾸고 싶어요 → load_image(), 상단 높이 설정
달리기 포즈를 읽고 싶어요 → load_run_frames()
게임 시작 준비가 궁금해요 → __init__()
새 판 준비가 궁금해요 → reset()
장애물 종류·위치가 궁금해요 → spawn_obstacle()
키 조작을 찾고 싶어요 → handle_events()
시간을 어떻게 나누는지 궁금해요 → update()
점프·이동·충돌·점수를 찾고 싶어요 → update_step()
그림·점수 위치를 바꾸고 싶어요 → draw()
기록을 읽고 쓰는 곳 → load_high_score(), record_high_score()
종료 준비를 하는 곳 → stop()
계속 반복시키는 곳 → run()
프로그램의 시작과 정리 → main()

처음 읽을 때 추천 순서:
상단 설정 → run → handle_events → update → update_step → draw
그다음 그림 로딩과 기록 저장을 읽어 보세요.


22. 검사와 현재 주의할 점

검사 파일은 test/test_game09.py예요.
프로젝트 폴더에서 다음 명령으로 실행해요.

python -B -m unittest discover -s test -v

검사는 게임이 약속대로 움직이는지 묻는 자동 문제집이에요.
점프와 착지, 충돌, 재시작, 기록, 장애물 크기, 모션, 정지 등을 확인해요.
실제 최고점수 대신 임시 파일을 사용해요.
직전 코드 작업에서는 11개 검사가 통과했어요.
이번 공부 노트 갱신에서는 게임 코드를 바꾸거나 검사를 다시 실행하지 않았어요.

검사 통과가 모든 재미와 자연스러움을 보장하지는 않아요.
포즈가 부드러운지, 발이 바닥에 맞는지, 충돌이 공정한지는 직접 봐야 해요.
기록 파일 오류 대응과 게임오버 중 정지 규칙도 개선할 부분이에요.

기능이 아직 없는 것:
시작 메뉴, 효과음, 밤 배경 전환, 코인, 동시 장애물, 점수별 난이도 증가.
제안 문서에 적힌 기능과 현재 구현된 기능을 구분해서 읽으세요.


23. 숫자 바꾸기 연습과 정답

먼저 답을 생각해 보고, 수정할 때는 한 가지씩 바꿔 보세요.

문제 1. x에서 숫자를 빼면 어느 방향으로 갈까요?
답: 왼쪽이에요.

문제 2. y가 작아지면 어느 방향으로 갈까요?
답: 위쪽이에요.

문제 3. RUN_FRAME_TICKS를 6에서 12로 바꾸면요?
답: 한 포즈가 0.2초 동안 보여서 달리기 포즈 전환이 느려져요.
네 포즈 한 바퀴는 0.8초가 돼요.

문제 4. FPS를 120에서 60으로 바꾸면 장애물 속도도 절반이 될까요?
답: 정상적인 시간 계산에서는 아니에요. 1초에 그리는 횟수가 줄어들어요.
장애물은 경과 시간에 맞춰 움직이므로 초당 이동 거리는 비슷해요.

문제 5. OBSTACLE_SPEED를 6에서 8로 바꾸면요?
답: 장애물이 초당 360픽셀에서 480픽셀로 빨라져요.
현재 BACKGROUND_SPEED도 이 설정을 사용하므로 배경도 빨라져요.

문제 6. PASS_BONUS를 10에서 20으로 바꾸면요?
답: 장애물 하나를 통과할 때 20점을 받아요.

문제 7. CHARACTER_HEIGHT를 180으로 바꾸면 상찌는 얼마나 클까요?
답: 현재 표는 CHARACTER_HEIGHT // 3을 사용하므로 높이 60이 돼요.
다른 위치와 충돌 설정도 함께 확인해야 해요.

문제 8. 점프를 더 높게 하려면 -15를 -18로 바꾸면 될까요?
답: 다른 조건이 같다면 처음 위로 향하는 속도가 커져 더 높이 뛰어요.
착지 시간도 달라져서 장애물 회피 감각을 다시 확인해야 해요.

문제 9. ESC를 누르면 최고점수를 저장하고 종료할까요?
답: 아니에요. 일시정지예요. 종료는 Ctrl+F4 또는 창 닫기예요.

문제 10. 왜 passed가 필요할까요?
답: 같은 장애물에서 점수를 여러 번 받지 않도록 기억하기 위해서예요.

이제 run()의 세 줄을 다시 읽어 보세요.
입력을 받고, 계산하고, 그려요.
이 반복 안에서 각 함수가 어떤 일을 하는지 찾아보면 게임 구조가 보이기 시작해요.
